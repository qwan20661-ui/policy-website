## 政策库规模

当前 111 条。扩展到千级、万级的应对见[开发计划第 11 节](开发计划.md#11-政策库规模扩展性)——**现在不实现，但二期的 `policy_index.py` 要把存储层收敛到四个函数**，避免万级规模时返工。

实测两个关键数字：确定性算分 25000 条/秒（单企业算 10000 条政策仅 0.4 秒，算分永不是瓶颈）；C9 通用政策占 69%（标签过滤不掉，这才是真瓶颈）。

## 贯穿全期的三条硬约束

**一、`unknown` 与"已核验的真实 0"必须区分。** `ipClass1Count=0` 是确认没有，创新活跃度记 0 分；`=null` 是不知道，该计分项从分母剔除。不造假、不用均值补造、不填默认值。

**二、C 标签只能是 docx 的 C1-C11 及子类编号。** 不引入政策库 `industryField` 词表（通用行业/生物医药/半导体和集成电路…）作为匹配轴，该字段只作打标时给模型看的证据。打标产出走枚举校验，非法值重跑。

**三、模型不算分、不判规则、不编政策。** 分数与规则判定全部由确定性函数完成，模型只负责编排、检索决策和写文案。`mode=deterministic` 是一等公民路径，既是降级兜底也是回归测试基准。

## 已知的最大变量

现有企业数据样本（3251 份）里，以下字段 100% 为空：`enterpriseCredit`、`techContractAmount`、`productServiceIntro`、`highTechField`、`enterpriseScale`、`hasRndAccount`、`hasRndInstitution`、`industryUniversityCoop`、`isInnovativeSme`、`isSpecializedSme`、`isSpecializedLittleGiant`、`isTechLeaderEnterprise`、`isInnovativeLeader`。`registerCapital` 仅 0.03% 有值。

由此 **11 条规则当前判不出**：R00（信用拦截）、R17（永久，接口无字段）、R19、R20、R23、R26、R37，以及受 C 子类 7% 覆盖率限制的 R08–R12。

规则代码全部照写，新接口补齐字段后无需改代码即可生效。**新接口这些字段是否有值，是影响方案实际效果最大的未决项**（见开发计划第 13 节）。
