## 实施结论

T4-T9 的代码、离线自动测试和接口契约已经完成。新条件匹配链路可独立调用，旧标签链路仍可通过功能开关保留为灰度与回滚路径。真实模型性能数据、典型企业人工结果和正式默认切换不在本次离线开发结果中，不能据此宣称业务验收已完成。

## T4 预过滤

新增 `service/match_prefilter.py`，只根据可验证事实执行排除，并为每项结果保留原因码和证据：

1. 信用负面整家拦截；
2. 前年及更早政策排除；
3. 明确的个人、高校等非企业主体排除；
4. 明确的属地、行业不符排除；
5. 资质成长图仅保留直接后继，空资质保留链路起点；
6. 研发补助的零专利、缺失专利及知识产权代理机构专属口径；
7. 规则表中可精确读取的成立年限、营收、员工、资产等不可逆上限；
8. 模糊文本或企业字段缺失时不预过滤。

## T5/T6 模型与评分

新增 `service/policy_match_model.py`、`service/condition_scoring.py`、`prompts/policy_condition_match_prompt.md` 和 `config/match_rules.json`。

1. 每条候选政策一次主模型调用，输出非法时最多重试一次；
2. 服务端生成稳定条件目录，模型只回填条件键，条件原文、组和操作符由服务端补充；
3. 模型只返回证据路径，证据值和说明由服务端回读，不可回读路径统一转为缺失分 10；
4. `gte/gt` 由服务端按 `actual / target * 100` 复算，`lte/lt` 超标触发不可逆排除；
5. AND 取平均，OR 取最高，正常组等权平均；
6. 时效分为当年进行中 100、未启动 85、已截止 70、去年 50，最终分为条件分 90% 加时效分 10%；
7. 模型不再重复计算条件总分和最终总分，服务端正式分是唯一汇总分来源。

### 2026-08-07 输入输出性能优化

模型输入输出协议升级为 v2，提示词版本同步升级，旧内存缓存会因版本变化自动失效：

1. 政策输入删除支持方式、文档、关联政策、质量标记和审计哈希，只保留标题、适用摘要、完整申报条件、原始规则表和关键词；
2. 企业输入由完整画像加 185 条重复事实改为单一事实表，删除旧标签、字段可用性、缺失字段、技术元数据和已标准化的原始重复项；
3. 规则表条件输出由 12 个字段加完整证据对象收缩为 7 个字段，证据只返回路径；
4. 删除未参与正式评分的 `policyApplicable`、模型汇总分和模型直接排除对象；直接排除由服务端根据已核验逐条件结果生成；
5. 样例企业的 64 条候选政策中，事实数从 185 降到 41；请求体 P50/P95 分别下降 76.0%/55.2%，结构化输出估算 P50/P95 分别下降 47.2%/54.7%；
6. 上述数据是离线 JSON 体积对比，不等同于真实模型耗时或 token 账单，真实 P50/P95 仍需重新批跑测量。
7. `run_condition_match_batch.py` 默认向 stderr 输出企业开始、预过滤统计、逐政策完成状态、模型耗时、排队、缓存、重试和企业汇总；`--quiet` 可关闭进度且不影响 stdout 的 JSON 汇总。

## T7/T8 编排与接口

新增 `service/match_orchestrator.py`、`service/match_cache.py` 和 `run_condition_match_batch.py`。

1. 单企业和批量共享同一编排器，批量保持输入顺序并隔离单企业、单政策失败；
2. 全部模型调用共享 `PEMATCHING_V2_POLICY_LLM_WORKERS` 全局信号量；
3. 缓存键包含企业画像哈希、政策内容哈希、模型、提示词和评分配置版本；相同键并发请求会等待同一主调用；
4. 新接口为 `POST /api/v2/condition-match/enterprise` 和 `POST /api/v2/condition-match/batch`，默认返回全部排序后的推荐，传 `topN` 后才分页；
5. `PEMATCHING_V2_ENGINE=condition_llm` 已作为默认值，既有 `/api/v2/tagmatch/*` 和独立条件接口均走新链路；显式改为 `legacy` 可回滚；
6. `GET /health` 新增 `conditionMatch`，输出模型并发、超时、缓存和评分配置状态；
7. `PEMATCHING_V2_MODEL_ARCHIVE_ENABLED=false` 默认关闭模型归档，开启时仅落已脱敏的企业和联系方式字段。
