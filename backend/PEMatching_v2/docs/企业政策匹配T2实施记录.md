## 1. 实施结论

T2“政策条件包”已完成，旧推荐链路和 A/B/C/D/E/F 标签行为未切换。

1. 新增 `service/policy_condition_package.py`，由代码确定性组装单政策条件包；
2. 新增 `schemas/policy_condition_package.schema.json`，并同步收紧模型输入 Schema；
3. 服务启动完成 T1 政策同步后，直接生成条件包快照；
4. 新增 `run_build_policy_condition_packages.py`，支持离线重建条件包；
5. 条件包生成不导入打标模块，不调用模型，不执行评分或业务排除；
6. 条件包和全库快照均带稳定 SHA-256 哈希，可序列化和回读校验。

## 3. 精简边界

模型条件输入保留：

1. 标题、摘要、行业、属地、场景、政策编码和有效期；
2. 申报对象、申报要求、申报说明和申报时间；
3. 支持方式、政策关键词、文档时效字段和一层关联关系；
4. 规则表全部结构。

明确移除：

1. `policyInfo.contactInfo` 联系方式；
2. 附件；
3. 申报材料；
4. 文档正文和其他与条件判断无关的大字段。

## 4. 质量标记

| 标记 | 含义 | 是否改变政策内容 |
|---|---|---|
| `ruleTableEmpty` | 没有硬性、软性或特殊通道评分项 | 否 |
| `hasUnresolvedItems` | 存在未绑定标准企业字段的规则项 | 否 |
| `hasLlmJudgeItems` | 存在语义或组合事实判断项 | 否 |
| `originalContainsOrExpression` | 原文出现“或、任一、满足其一”等表达 | 否 |
| `suspectedOrOperatorMismatch` | 原文疑似 OR，但现有规则组全部为 AND | 否，仅记录风险 |
| `hasEmptyTargetValues` | 任意规则目标值为空 | 否 |
| `hasMissingRequiredTargetValues` | 定量运算符缺少目标值 | 否，仅记录警告 |

质量标记只记录问题，不丢弃政策，也不在 T2 阶段修正规则。

## 5. 新增注意事项处理

根据问题清单补充的“定性与定量区分”要求：

1. `llm_judge` 等定性条件目标值为空，只记录 `EMPTY_TARGET_VALUES` 信息；
2. `gte/gt/lte/lt/eq/between` 等定量运算符目标值为空，额外记录 `MISSING_REQUIRED_TARGET_VALUES` 警告；
3. 数值 `0` 是有效目标值，不得按空值处理；
4. T2 不根据标题、关键词或支持方式擅自改变硬性/软性分类；
5. 信用、行业、属地、资质链、研发投入和时效排除属于 T4/T6，不在条件包阶段提前执行。

## 6. 代表政策验证

2. 6509：保留完整原文和 2 个规则项，标记 2 个 `unresolved`、1 个 `llm_judge`；

6451 当前接口 `reviewStatus=0`，不会进入 T1 的 76 条运行快照；T2 使用冻结夹具验证其历史代表性问题，不绕过 T1 审核过滤。
