# 第五期资格门禁接口

`POST /api/v2/eligibility/evaluate`

接口默认关闭。启用前设置：

```powershell
$env:PEMATCHING_V2_ELIGIBILITY_ENABLED='true'
```

请求中的 `fusionPolicyIds` 必须来自已经完成排序的 V2 推荐结果；接口保持该数组顺序，不会召回、筛选或排序政策。

```json
{
  "enterprise": {"enterpriseName": "示例企业"},
  "fusionPolicyIds": ["6548", "6590"],
  "includeConditionDetails": true,
  "requestId": "caller-optional-id"
}
```

响应在 `data.eligibilityEvaluations` 返回每条政策的 `gateStatus`、`conditionMatchScore`、证据计数和可选条件明细。`meta.runId` 是完整归档的安全关联标识；它不是 V2 推荐请求 ID。

| 状态 | 含义 | 是否允许资格直推 |
|---|---|---:|
| `direct_push` | 规则、证据和分数满足门禁，或真实精确证据命中直通车 | 是 |
| `needs_supplement` | 存在缺失、拒绝、未知分支、不可计算或规则不完整 | 否 |
| `not_recommended` | 硬条件明确失败，或全部条件确认后分数低于 60 | 否 |
| `not_evaluable` | 无规则、空规则或规则非法 | 否 |

资格结果不会覆盖 V2 的 `totalScore`、`baseScore`、`bonusScore`、`band`、`rank`、`reason`、`matchedRules`，也不会增删 V2 `recommendations`。
