# 企业政策匹配 T0/T1 实施记录

> 实施日期：2026-08-06  
> 规则基准：[企业政策匹配新规则.md](企业政策匹配新规则.md)  
> 开发计划：[企业政策匹配重构开发计划.md](企业政策匹配重构开发计划.md)

## 1. 实施结论

T0 与 T1 已完成，旧匹配接口行为暂未切换。当前形成以下稳定边界：

1. `企业政策匹配新规则.md` 是新链路唯一业务规则基准；
2. 模型输入、模型输出和新响应分别使用独立 JSON Schema；
3. 三条代表性政策和三类企业样例已保存为离线测试夹具；
4. 服务启动时完整同步一次审核政策，运行期间不自动刷新；
5. 任何列表不完整或单条详情失败都不会切换新快照；
6. 新快照带政策内容指纹和全库版本哈希；
7. 同步失败时使用旧快照并标记 `degraded`，无旧快照时不进入就绪状态；
8. 资格规则迁移复用统一政策快照，不再在启动阶段重复拉取全部政策详情。

## 2. T0 产物

### 2.1 JSON Schema

| 文件 | 用途 |
|---|---|
| `schemas/policy_condition_match_input.schema.json` | 单政策模型输入 |

## 4. T1 启动状态

健康接口新增 `policySync`：

```text
status              not_started / syncing / ready / degraded / unavailable
ready               是否允许服务进入就绪状态
policyCount         当前可用政策数
version             当前全库版本哈希
snapshotFetchedAt   当前快照生成时间
lastAttemptAt       最近同步尝试时间
source              政策接口来源
degradedReason      降级或不可用原因
```

启动顺序固定为：政策同步与完整性校验 → 原子切换 → 清理政策索引缓存 → 从政策快照迁移资格规则 → 旧链路增量打标。T3 实施前仍保留旧标签启动任务用于灰度和回滚。
