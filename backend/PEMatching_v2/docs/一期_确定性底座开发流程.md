### 3.3 `service/taxonomy.py`

```python
def load_taxonomy() -> Dict[str, Any]                      # 读 tag_taxonomy.json，lru_cache
def load_industry_map() -> Dict[str, Any]                  # 读 industry_to_c_tag.json，lru_cache
def load_keyword_library() -> Dict[str, Any]               # 读 keyword_library.json，lru_cache
def is_valid_tag(dimension: str, value: str) -> bool       # 枚举校验，二期打标要用
def validate_tag_payload(tags: Dict) -> List[str]          # 返回非法项列表，空表示合法
def resolve_c_tags(level1: str, level2: str) -> Tuple[List[str], str]
                                                           # 返回 (cTags, confidence)，未命中返回 ([], "none")
def match_c_subtags(text: str) -> List[str]                # 关键词匹配子类
def match_regions(district: str, zone: str, address: str) -> List[str]
def has_credit_negative(text: str) -> bool
```

**要点**：全部 `lru_cache`；配置文件缺失或 `schemaVersion` 不匹配时抛 `ValueError` 并指明文件路径，不静默用默认值。

**测试** `tests/test_taxonomy.py`：
- 三个配置能加载，`schemaVersion` 校验生效
- `is_valid_tag("C", "C1.2")` True；`is_valid_tag("C", "通用行业")` False（防政策库词表污染，二期依赖此断言）
- `resolve_c_tags` 三级优先：level2 命中 / level2 未命中降 level1 / 都未命中返回 `([], "none")`
- `match_c_subtags` 大小写不敏感（`oled` 能命中 `OLED`）
- `match_regions` 三级回退：仅有 address 时也能出结果

## 4. T2：run_build_industry_map.py（一次性离线）

**唯一需要 LLM 的一步，产物入库后本期其余部分不再调模型。**

1. 扫 `backend/PEMatching/企业测试目录/*.json`，统计 `industryLevel1`/`industryLevel2` 全部取值及出现次数（实测：level1 共 11 种、level2 约 30 种，封闭集合）

### 5.2 输出结构

```python
{
  "enterpriseName": str,
  "creditCode": str,                    # 缺失时空串，不 None
  "tags": {
    "B": ["B2"],                        # 可多个；三信号全缺时 []
    "C": ["C1"],                        # 大类
    "cSub": ["C1.3"],                   # 子类
    "regions": ["思明区"],
  },
  "metrics": {
    "companyAgeYears": 9.8 | None,
    "employeeCount": 108 | None,
    "revenueWan": 2399.52 | None,       # 元 → 万元
    "ipTotal": 11 | None,               # ipClass1+ipClass2 → ipCount → inventionPatentCount
    "ipSource": "ipClass1+2" | "ipCount" | "inventionPatentCount" | None,
    "rdExpenseWan": 735.39 | None,
    "techContractWan": None,
    "doctorCount": None, "masterCount": None,
    "newRecruitCount": None, "collegeGraduateCount": None,
  },
  "qualifications": {                   # 只有明确"是"才 True；null 记 unknown
    "isTechSme": True,
    "isHighTechEnterprise": True,
    "isInnovativeSme": None,
    "isSpecializedSme": None,
    "isSpecializedLittleGiant": None,
  },
  "credit": {"checked": False, "negative": None, "raw": None},
  "fieldAvailability": {                # 每个下游要用的字段一条
    "registerDate": "available",
    "industryLevel2": "available",
    "enterpriseCredit": "unknown",
    "registerCapital": "unknown",
    ...
  },
  "dataCompleteness": {"available": 12, "unknown": 9},
}
```

### 5.3 硬性要求

| 要求 | 说明 |
|---|---|
| **`0` 与 `null` 必须区分** | `ipClass1Count=0` → `ipTotal=0` + `fieldAvailability="available"`；`=null` → `ipTotal=None` + `"unknown"`。这条是全期最容易写错的地方 |
| 单位换算 | `operatingIncome`/`rdExpense`/`techContractAmount` 接口给的是**元**，内部统一万元；`registerCapital` 接口已是万元（虽然实测不可用） |
| 子表取最新年度 | `operationInfoList` 按 `year` 降序取第一条有值的；不同指标可来自不同年度时，以 `year` 最大的那条为准并记录 `metricsYear` |
| `registerCapital` 与 `enterpriseScale` 不参与规模判定 | 实测 0.03% / 0%，按开发计划 3.3 节 |
| B 维度多归属 | 三信号"或"逻辑，一个企业可同时是 B2 和 B3，不取唯一值 |
| 不造数 | 任何字段缺失都不填默认值、不用均值。老链路 `enterprise_feature_defaults.json` 那套均值补造机制**不移植** |

### 5.4 测试 `tests/test_profile.py`

必须覆盖的用例：

1. 全字段齐全（用 `2252_测试企业名称1.json` 真实数据）
2. **仅必填字段**：只有 `registerDate` + `registerAddress` + `employeeCount`，断言 B 和 regions 仍能算出、C 为 `unknown`
3. **`0` vs `null`**：两条记录仅 `ipClass1Count` 分别为 `0` 和 `null`，断言 `ipTotal` 与 `fieldAvailability` 都不同
4. 子表为空数组 / 子表为 `null` 两种情况都不抛异常
5. 单位换算：`operatingIncome=23995200` → `revenueWan=2399.52`
6. B 多归属：造一个成立 10 年但营收 1000 万的企业，断言 B 同时含 B1 和 B3
7. `today` 注入：固定 `today=date(2026,8,3)` + `registerDate=2016-10-13`，断言 `companyAgeYears` 稳定
8. 知产三级回退：分别只给 `ipCount` / 只给 `inventionPatentCount`，断言 `ipSource` 正确

## 7. T5：scoring.py

### 7.1 函数签名

```python
def score_policy(profile: Dict, policy_tags: Dict, keyword: str = "",
                 today: date | None = None,
                 matched_rule_ids: List[str] | None = None) -> Dict[str, Any]
```

### 7.2 输出结构

```python
{
  "totalScore": 92, "baseScore": 82, "bonusScore": 10, "band": "direct_push",
  "baseDetail": {
    "items": [{"name": "领域匹配度", "weight": 30, "score": 25,
               "basis": "企业 C1 与政策 C1 大类精确匹配"}],
    "effectiveWeight": 90,
    "excludedItems": [{"name": "信用记录", "weight": 10, "reason": "enterpriseCredit 无值"}],
    "rawSum": 73.8, "normalized": 82.0,
  },
  "bonusDetail": {"items": [...], "capped": False},
}
```

### 7.3 计分要点

| 项 | 实现要点 |
|---|---|
| 领域匹配度 | 四档：子类交集 30 / **大类精确交集 25** / 政策仅 C9 通用 10 / 无交集 0。25 分档是本方案对 docx 的调整，理由见开发计划 3.1.1 |
| 归一化 | `baseScore = rawSum / effectiveWeight × 100`，`effectiveWeight` 为 0 时（全部字段缺失）返回 `baseScore=None` + `band="not_evaluable"`，不返回 0 分 |
| 关键词四级 | **取最高一级不叠加**。命中标题就不再算 A/C/正文 |
| 时效性三档 | 互斥。`applicationWindow=null` 时该项 0 分并在 basis 注明 |
| 2025 年 +8 | docx 特例，写在配置不写死代码 |
| 附加分封顶 | `min(sum, 50)`，封顶时 `capped=True` |
| 链路加成 | 依赖 `policy_tags.growthChain.prerequisite` 与企业资质比对 |

### 7.4 测试 `tests/test_scoring.py`

- 五项全有效：手工算出期望分，断言精确相等
- 逐项剔除：每次剔除一项，断言 `effectiveWeight` 与归一化结果
- `effectiveWeight=0` → `band="not_evaluable"` 且 `baseScore is None`
- 领域匹配度四档各一个用例
- 关键词四级：造一个同时命中标题和 C 类的场景，断言只加 20 不加 30
- 时效性三档 + `applicationWindow=null` 四个用例
- 附加分封顶：造一个总和 > 50 的场景
- 阈值边界：79/80、59/60 各一个用例

## 8. T6：run_phase1_stats.py

跑全量 3251 份，产出 `output/phase1_stats.xlsx`，**这份统计是四期阈值校准的输入，不是可选项**。

必须包含的表页：

1. **字段填充率**：复现开发计划 2.2 节的表，确认与文档记录一致（若不一致说明样本或读取逻辑有问题）
2. **规则三态分布**：34 条规则各自的 命中数 / 未命中数 / 跳过数 / 跳过原因分布
3. **标签分布**：B 各阶段企业数、C 大类分布、C 子类命中数（预期极低）、属地分布
4. **基础分分布**：分「有 industryLevel2」与「无 industryLevel2」两组，各自的分位数（P10/P25/P50/P75/P90）与直方图数据
5. **effectiveWeight 分布**：多少企业有几项有效计分项

**验证**：
```powershell
python backend/PEMatching_v2/run_phase1_stats.py --limit 50    # 先小样本跑通
python backend/PEMatching_v2/run_phase1_stats.py               # 全量
```

第 4 项的两组对比是关键——若两组分数分布差异过大，说明归一化没能真正拉平信息量差异，需要在四期调整或引入信息量惩罚项。
