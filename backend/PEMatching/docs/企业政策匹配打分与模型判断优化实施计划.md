# 企业政策匹配打分与模型判断优化实施计划

> 创建日期：2026-07-31
> 适用接口：`POST /api/pematching/match/enterprise`
> 执行要求：后续开发必须先阅读本文档、《问题.md》、《企业政策匹配接口文档.md》和《企业政策匹配打分规则说明.md》。

## 1. 背景与问题

《问题.md》原始问题：

> 1：现在会有：未推荐原因 1阻断政策申报截止日为2025-04-12，当前申报窗口已结束。不应该有这种判断，只从政策申报要求中进行匹配，不要有这种阻断什么的；我只要企业数据能否匹配上政策给的规则要求；
>
> 2：修改计算分数：企业没有数据，先给匹配分10（兜底），如果企业有数据 30分，看数据情况，去评估，比如说要求超过50人，企业只有3人。30+100/50*3=36分。其余定量的也是这样

旧行为会使用截止日期、地域和主体推断阻断推荐，缺失字段默认记70分，下限型指标使用1.5倍成长性公式。目标行为是只按政策规则要求评价企业数据，将缺失默认分改为10分，并采用已确认的10/30/100评分口径。

## 2. 已确认决策

| 项目 | 决策 |
|---|---|
| 缺失数据 | 条件得10分，继续标记 `default_missing_assumed`，不计为真实证据 |
| 有数据基础分 | 普通不满足条件最低30分；下限型按比例继续加分 |
| 硬性条件 | 明确不满足得0分，并使政策最终分归零 |
| A/B体系 | 保留为运行时证据质量审计标签；A1/A2为核验证据，B为辅助证据，不再决定总分权重 |
| 类别内权重 | 条件等权；缺失条件不再半权 |
| 推荐阈值 | 保留60分 |
| 定性系数 | 取消二次放大，兼容字段 `coeff_C` 固定为1.0 |
| 直通车 | 真实证据命中后最低90分；缺失假定不得触发 |
| 科技型中小企业评价 | 保留官方分档，缺失维度按对应满分的10%补足 |
| 规则外守卫 | 移除截止日、地域、自然人、药械主体和技术转移机构阻断 |
| 模型职责 | 只判断事实、证据、分支和标准化候选值；本地代码负责算分 |

## 3. 条件评分公式

内部使用 `0.0-1.0`，对外统一转换为百分制。

| 条件 | 普通/软性条件 | 硬性条件 |
|---|---|---|
| 企业数据或有效证据缺失 | 0.1 | 0.1，不直接失败 |
| `gte` / `gt` 有值 | `min(1, 0.3 + 企业值 / 目标值)` | 满足得1，不满足得0并归零 |
| `lte` / `lt` | 满足得1，超限得0.3 | 满足得1，超限得0并归零 |
| `equals` | 相等得1，不等得0.3 | 相等得1，不等得0并归零 |
| `has_value` | 有值得1，缺失得0.1 | 有值得1，缺失得0.1 |
| 定性 `supported` / `contradicted` / `missing` | 1 / 0.3 / 0.1 | 1 / 0并归零 / 0.1 |
| `not_applicable` | 跳过，不进入分母 | 跳过，不进入分母 |
| `unknown` | 0.1 | 0.1 |
| 规则不可计算 | `not_evaluable`，不进入分母并阻止推荐 | 同左 |

边界规则：显式0是有效数据；严格比较符必须尊重相等边界；目标值0按比较符直接判断，不做除法；负数、非数值目标和单位无法换算进入 `not_evaluable`。

## 4. 总分、推荐与专项

- 所有适用且可评分条件逐条同权平均；缺失10分与其他条件权重相同。
- A/B只输出运行时证据层级统计，不再使用固定70%/30%改变最终分。
- `skipped`、`not_evaluable` 和直通车条件不进入普通A/B分母。
- `coeff_C` 固定为1.0，不再按模型置信度二次放大。
- 推荐条件为：无硬性失败、无 `not_evaluable`、最终分不低于60。
- 直通车仅由真实证据触发，不能绕过硬性失败或待确认。
- 科技型中小企业部分维度缺失按该维度满分的10%补足；全部缺失时条件得10分。

## 5. 模型职责与证据校验

模型输出协议保持 `supported`、`contradicted`、`missing`，不得输出业务分数。服务端必须校验人员指标、比例分子分母、主体角色、资质荣誉、地址层级、知识产权类型、年度和单位的语义兼容性。

不兼容事实统一降级为 `missing`，清空映射字段、标准化值、单位、展示值和证据，记录 `errorCode=semantic_evidence_incompatible` 及“语义证据类型校验拒绝”原因，再由本地评分记10分。

## 6. API兼容策略

| 字段 | 新语义 |
|---|---|
| `matchScore` | 新10/30比例公式、A/B权重和专项规则形成的匹配分 |
| `isRecommended` | 规则评分达到60且无硬性失败、无不可计算项 |
| `matchStatus` | 正常完成固定为 `matched`，不再产生规则外 `资格不满足` |
| `recommendationBlockers` | 保留字段，正常结果固定为空数组 |
| `evidenceRatio` | 只统计真实证据，缺失10分和专项补足不计入 |
| `coeff_C` | 归档和Excel兼容字段，固定为1.0 |

请求体、查询参数、`runId`、归档位置、模型重试状态及失败时 `matchScore=null` 的语义保持不变。

## 10. 回滚点

1. 评分回滚：条件公式、A/B聚合和专项比例集中回滚，不影响模型调用协议。
2. 守卫回滚：规则外资格守卫调用独立于本地评分，可单独恢复或移除。
3. 模型校验回滚：确定性语义校验位于模型事实与本地评分之间，可单独关闭而不改变API结构。
