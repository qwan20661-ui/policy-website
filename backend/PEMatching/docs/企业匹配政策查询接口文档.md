# 企业匹配政策查询接口文档

**文档版本：** v1.2<br>
**更新日期：** 2026-07-31  

## 1. 接口范围

| 能力 | 方法与路径 | 说明 |
|---|---|---|
| 查询企业最新匹配结果 | `GET /api/pematching/match/enterprise` | 按企业 ID 返回该企业最近一次成功保存的政策匹配结果 |
| 查询已有匹配结果企业 | `GET /api/pematching/match/enterprises` | 分页返回已有匹配结果的企业，每个企业仅返回最新一条运行记录 |

地址：http://127.0.0.1:33044

## 2. 查询企业最新匹配结果

### 2.1 请求定义

```http
GET /api/pematching/match/enterprise?enterpriseId=292733
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `enterpriseId` | string | 是 | 企业唯一标识；必须与该企业已保存匹配结果中的企业 ID 一致 |

#### Postman cURL 示例

```bash
curl --location 'http://127.0.0.1:33044/api/pematching/match/enterprise?enterpriseId=292733'
```

#### 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.policies` | array | 本次保存的政策匹配结果列表 |
| `meta.found` | boolean | 是否已找到该企业的历史匹配结果 |
| `meta.runId` | string | 最近一次匹配运行的关联标识 |
| `meta.policyCount` | integer | 最近一次运行实际参与匹配的政策数量 |
| `meta.createdAt` | string | 最近一次结果保存时间 |

#### `data.policies[]` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `fusionPolicyId` | string | 主政策唯一标识 |
| `mainFileTitle` | string | 政策标题 |
| `applicationStartTime` / `applicationEndTime` | string / null | 申报起止时间 |
| `issuingDepartment` | string / null | 发文部门 |
| `matchScore` | number / null | 匹配分数；为 `null` 表示本次政策匹配未完成，不能按 0 分展示 |
| `level` | integer / null | 匹配星级：`0` 表示不匹配（`0` 至 `1` 分），`1` 表示 `(1, 40]` 分，`2` 表示 `(40, 60]` 分，`3` 表示 `(60, 70]` 分，`4` 表示 `(70, 90]` 分，`5` 表示 `(90, 100]` 分；`matchScore` 为 `null` 时本字段也为 `null` |
| `isRecommended` | boolean / null | 是否推荐；为 `null` 时尚未形成有效推荐结论 |
| `evidenceRatio` | number / null | 已核验条件在计分条件中的占比，用于区分证据充分度 |
| `confidenceLevel` | string / null | 结果置信等级；未产生统计时为 `null` |
| `verifiedConditionCount` | integer / null | 有企业真实证据支持的条件数量 |
| `assumedConditionCount` | integer / null | 因企业信息缺失而按默认/待确认口径处理的条件数量 |
| `scoredConditionCount` | integer / null | 参与评分的条件数量 |
| `maxAmount` | string / null | 政策最高支持金额原文 |
| `documents` | array | 政策类型摘要，每项仅包含 `policyTitle` |
| `applicableScope` | string / null | 适用范围 |
| `industryField` / `industryFieldPath` | string / null | 政策行业领域及路径 |
| `supportMethods` | string[] | 支持方式文本列表 |

### 2.3 无结果响应

未查到该企业时仍返回 HTTP `200`。调用方应依据 `meta.found` 而非仅依据状态码判断：

```json
{
  "success": true,
  "data": { "policies": [] },
  "meta": {
    "found": false,
    "runId": "",
    "policyCount": 0,
    "createdAt": null
  }
}
```

### 2.4 错误响应

```json
{
  "success": false,
  "message": "缺少 enterpriseId 参数"
}
```

| HTTP 状态码 | 典型原因 | 调用方建议 |
|---:|---|---|
| `400` | 缺少 `enterpriseId` | 补充有效企业 ID 后重新查询 |
| `405` | 使用了非 GET 方法 | 使用 GET 请求 |
| `500` | 查询服务或已保存结果数据异常 | 记录企业 ID 和请求时间，联系服务方排查 |
| `503` | 根服务无法连接查询服务 | 采用退避重试，并通知服务方检查服务状态 |

## 3. 查询已有匹配结果的企业

### 3.1 请求定义

```http
GET /api/pematching/match/enterprises?page=1&size=20&enterpriseName=测试
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `page` | integer | 否 | `1` | 页码，从 1 开始；兼容 `pageNum`、`pageNumber` |
| `size` | integer | 否 | `20` | 每页数量，范围 `1` 至 `100`；兼容 `pageSize` |
| `enterpriseName` | string | 否 | 空 | 企业名称模糊查询 |

列表按企业 ID 去重，每个企业仅返回最新一次匹配运行，不返回完整政策数组。

#### Postman cURL 示例

```bash
curl --location --request GET "http://http://127.0.0.1:33044/api/pematching/match/enterprises?page=1&size=20&enterpriseName=测试" \
  --header "Accept: application/json"
```

### 3.2 成功响应

```json
{
  "success": true,
  "data": [
    {
      "enterpriseId": "900",
      "enterpriseName": "厦门示例科技有限公司",
      "creditCode": "913502000000000900",
      "latestRunId": "8db4f59cbce84220ad2d4a6ce8c6446e",
      "policyCount": 115,
      "latestMatchedAt": "2026-07-31 12:00:00.000000"
    }
  ],
  "pagination": {
    "page": 1,
    "size": 20,
    "total": 1,
    "pages": 1
  }
}
```

| 字段 | 说明 |
|---|---|
| `data[].enterpriseId` | 企业唯一标识 |
| `data[].enterpriseName` | 最近一次匹配时的企业名称快照 |
| `data[].creditCode` | 最近一次匹配时的统一社会信用代码快照，可为空 |
| `data[].latestRunId` | 最近一次匹配运行标识 |
| `data[].policyCount` | 最近一次运行实际参与匹配的政策数量 |
| `data[].latestMatchedAt` | 最近一次匹配结果保存时间 |
| `pagination.total` | 去重后的企业总数，不是匹配运行记录总数 |
