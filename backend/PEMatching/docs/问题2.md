# 问题2：A/B 总分过度依赖规则表预分类

> 记录日期：2026-07-31  
> 状态：已确认实施，采用运行时证据分层与条件均衡评分

## 1. 问题描述

当前规则引擎以政策规则表中每个条件项的 `matchRule.ruleKind` 决定 A/B 总分归类：

| 规则表 `ruleKind` | 当前总分归类 |
|---|---|
| `direct` | A 类直接分 |
| `reference`、`supporting`、`proxy`、`derived` 或其他非 `direct` 值 | B 类间接分 |

这意味着 A/B 归类在政策提取/规则表生成阶段已经预先固定。运行时模型虽然会输出 `supported`、`contradicted`、`missing`、证据路径和标准化值，但不会根据企业实际证据重新判断“该证据是否与政策条件语义完全等价”。

## 2. 风险与影响

| 风险 | 说明 |
|---|---|
| 规则表预判替代运行时事实判断 | 同一政策条件面对不同企业数据，其实际可证明程度可能不同；仅依赖静态 `ruleKind` 无法表达这种差异。 |
| 非直接字段被统一当作 B 类 | 当前实现将所有 `ruleKind != direct` 的项放入 B 类，无法区分确定派生、弱代理、缺失映射和未知类型。 |
| 缺失事实被误读为间接证据 | “企业字段无对应内容”本质是无证据，不应被表述为正向的间接匹配。 |
| 严格资格与推荐召回混淆 | 代理或关联线索可帮助排序，但不能证明企业严格满足政策申报资格。 |
| 展示字段语义冲突 | 明细字段“评分组别”目前按硬性组写 A、软性组写 B；总分 A/B 则按 `ruleKind` 分桶，两者不是同一概念。 |

## 3. 应遵循的边界

1. 规则表继续定义政策条件：原文、比较符、阈值、单位、分支和适用范围。
2. A/B 不再直接由规则表 `ruleKind` 决定，而应由运行时的“政策条件 × 企业证据”语义兼容结果决定。
3. 模型只提供事实和证据候选；最终分类必须由服务端确定性校验完成，不能由模型计算总分或自判权重。
4. 无字段映射、无有效证据、语义冲突必须单列为 `unmapped`、`missing` 或 `semantic_incompatible`，不能作为正向 B 类证据。
5. 严格资格判断只能使用语义完全一致或可完整追溯的确定派生证据；代理证据只能作为推荐/补证提示。

## 4. 建议的运行时证据分层

将政策条件标准化为政策事实契约，将企业数据标准化为企业事实，再按事实关系产生运行时 `evidenceTier`：

| 分层 | 判定条件 | 对严格资格的作用 | 建议评分用途 |
|---|---|---|---|
| `A1_exact` | 指标、主体/角色、年份、统计范围、比较对象、单位和分支均一致 | 可以证明 | 计入严格分与推荐分 |
| `A2_derived` | 可由确定公式推导，全部输入字段、年份、单位和公式可回溯 | 可以证明，需记录公式 | 计入严格分与推荐分；是否与 A1 同权待确认 |
| `B_supporting` | 存在显式允许的关联、辅助或代理关系，但不构成等价证明 | 不可以证明 | 仅计入推荐/发现分，或仅作展示 |
| `unmapped` | 企业快照无对应字段，且不存在允许的派生/关联关系 | 不可以证明 | 不作为正向 B 类，不计入正向分 |
| `missing` | 字段定义可对应，但当前企业没有有效值或证据 | 不可以证明 | 作为补证提示；缺失分规则需与严格分分离 |
| `semantic_incompatible` | 模型返回的字段/证据与政策事实不兼容 | 不可以证明 | 拒绝该证据并记录审计原因 |

### 4.1 A1 精确判定最小校验维度

| 维度 | 示例 |
|---|---|
| 指标语义 | `研发人员占比` 不等于 `本科及以上员工占比` |
| 主体与角色 | 企业资质不能证明法定代表人的个人荣誉 |
| 时间 | 当年、上一年度、近三年不能混用 |
| 统计范围 | 单体企业、集团合并、项目口径、全体员工口径需一致 |
| 比较双方 | 注册地址不等于项目实施地；企业自身不等于关联企业 |
| 单位与分母 | 比例的分子/分母必须完整且一致；万元/亿元必须可验证换算 |
| 证据来源 | 必须能回指企业 JSON 路径、原始文本或本地派生公式 |

## 5. 可选评分方案

| 方案 | 设计 | 优点 | 代价与风险 |
|---|---|---|---|
| 一：运行时重判 A/B | A 为精确/可追溯派生，B 为真实辅助证据，无映射不进 B | 保留现有 A/B 框架，改造相对渐进 | 仍需定义哪些代理关系允许进入 B |
| 二：双分制（推荐） | `strictScore` 只使用 A1/A2；`discoveryScore` 使用 A1/A2/B | 严格资格与召回排序彻底分离，语义最清晰 | 接口、页面、Excel 和归档需增加字段并迁移展示 |
| 三：B 不参与总分 | 最终分只使用 A1/A2；B 仅作为提示 | 最保守、可解释性最高 | 企业数据不完整时推荐排序信息减少 |

建议优先采用方案二：

```text
strictScore    = A1_exact + A2_derived
discoveryScore = A1_exact + A2_derived + B_supporting

isRecommended（严格）仅依赖 strictScore、硬性条件和待确认门禁。
B_supporting 只能影响排序、人工复核优先级和补充材料建议。
```

### 9.1 6543误推荐的根因

当前计算为：

```text
A类：营业收入满足 = 100
B类：9项缺失条件平均 = 10
最终分 = 100 * 70% + 10 * 30% = 73
```

这个结果算术正确，但政策语义不合理。固定类别权重使一条A类条件可以压过大量未核验的核心条件，实际等于让规则表的静态字段分类决定了推荐，而不是让政策全部要求共同决定推荐。

## 10. 已采用算法：运行时证据分层与条件均衡评分

本轮不引入新的模型评分 Agent。采用确定性本地算法 `Runtime Evidence Tiering and Balanced Scoring`，中文名称为“运行时证据分层与条件均衡评分算法”。

### 10.1 分析流程

| 步骤 | 输入 | 本地处理 | 输出 |
|---|---|---|---|
| 1. 政策事实化 | 规则表中的原文、操作符、目标、单位、分支 | 只读取规则，不读取 `ruleKind` 决定总分 | 政策事实契约 |
| 2. 企业事实化 | 企业原始JSON和标准化快照 | 保留值、单位、年份、主体、来源路径及派生公式 | 企业事实候选 |
| 3. 证据校验 | 模型事实候选或本地字段 | 校验路径、语义类别、主体、年份、统计范围、单位和比例 | 有效事实或拒绝原因 |
| 4. 运行时分层 | 已校验事实、映射方式、派生标记 | 确定性分类为A1/A2/B/U/R | `evidenceTier`、`bucketReason` |
| 5. 条件评分 | 企业值和政策操作符 | 按10/30/100及硬性规则计算 | 条件分 |
| 6. 总分聚合 | 所有参与计分条件 | 每条条件同权平均；A/B不再改变权重 | `final_score` |
| 7. 推荐判定 | 总分、硬性失败、不可计算项 | 阈值60，保留直通车规则 | 推荐状态 |

### 10.2 运行时证据层级

| 层级 | 含义 | 判断依据 | 是否计入证据覆盖率 | 是否参与条件总分 |
|---|---|---|---|---|
| `A1_exact` | 精确企业事实 | 有效路径或本地字段，指标、主体、年份、范围和单位一致 | 是 | 是 |
| `A2_derived` | 确定性派生事实 | 本地公式可回溯，全部输入和单位有效 | 是 | 是 |
| `B_supporting` | 辅助线索 | 显式代理/辅助关系，但不能等价证明政策条件 | 是，但单独统计 | 是；条件本身仍与其他条件同权 |
| `U_missing` | 可定义但企业数据缺失 | 无有效企业值或模型状态为 `missing` | 否 | 是，按缺失得10分 |
| `R_rejected` | 证据被拒绝 | 路径、语义类别、主体、年份、范围或单位不兼容 | 否 | 是，按缺失得10分 |
| `N_not_evaluable` | 规则不可计算 | 规则目标、单位或结构不合法 | 否 | 否，并阻止推荐 |
| `S_skipped` | 分支不适用 | `not_applicable` | 否 | 否 |

### 10.3 新总分公式

```text
条件分 = 原有10/30/100、本地数值比例、硬性和专项规则

final_score = 所有参与计分条件分的算术平均
```

A/B字段保留用于审计，不再使用固定70%/30%改变总分：

```text
score_A_direct   = A1_exact 与 A2_derived 条件平均分
score_B_indirect = B_supporting 条件平均分
unverifiedScore = U_missing 与 R_rejected 条件平均分
```

现有 `score_A_direct`、`score_B_indirect` 字段继续保留，避免旧消费者因字段删除失败；字段说明迁移为运行时证据层级统计。新增明细字段 `evidenceTier` 和 `bucketReason`，用于解释每条条件为何进入对应层级。

### 10.4 固定样本预期

| 场景 | 旧分数 | 新算法预期 |
|---|---:|---:|
| 6543：1项100分、9项缺失10分 | 73 | `(100 + 9*10) / 10 = 19`，不推荐 |
| 6548：当前漏字段状态 | 28.23 | `(100 + 10 + 10 + 73 + 100) / 5 = 58.6`，不推荐且明确缺字段 |
| 6548：字段映射修复后 | 约99.55 | `(100 + 100 + 100 + 94 + 100) / 5 = 98.8`，推荐 |
| 全部条件缺失 | 10 | 10，不推荐 |

| 分数表现 | 审计结果 | 是否属于企业不满足 | 处理结论 |
|---|---|---|---|
| 最终分10 | 共39条政策，参与计分条件全部为 `default_missing_assumed`，且已核验条件数为0 | 不能据此判断不满足；表示企业快照没有该政策所需的可核验事实 | 保留10分作为召回/补证提示，不推荐。典型缺失：人才年薪、负责人经历、技术服务收入、工业产值、场地、项目或特定资质。 |
| 条件分10且企业值非空 | 发现4项候选字段误展示：`6501` 把职工总数108展示为科技人员占比；`6579`、`6549`、`6639` 把通用“企业资质=是”展示为实验室主任职称、小微企业标准、施工资质 | 不是企业事实，模型已正确判为 `missing`，但展示层误导 | 修复评分明细：`default_missing_assumed` 的定性条件统一清空企业值、解析字段和解析值，只保留缺失原因。 |
| 最终分0 | 共65条政策，`scoredConditionCount=0`、`assumedConditionCount=0`、无条件明细 | 不是企业不符合，也不是企业资料缺失 | 该政策当前没有可执行规则项，0仅是空条件集合的技术默认值；必须通过计分条件数识别，不能解释为资格失败。 |

### 13.1 结论与接口使用约束

1. `10` 是“规则可计算但企业缺少有效事实”的低置信度得分；它不等于企业不符合，也不等于模型已经作出否定判断。
2. `0` 且 `scoredConditionCount=0` 是“无可执行规则”的未评估状态，不是条件失败；前端应展示为“待补规则”，不能展示为“0分不符合”。
3. 真正的明确不满足应在条件明细中体现为 `evalStatus=fail`；若属于硬性条件，最终分才会归零。当前固定样本的65条0分政策均不属于此类。
4. 后续应在轻量API增加不破坏兼容的 `scoringState`/`scoringReason`，把“已评分”“无可执行规则”“硬性失败”显式区分；本轮先通过既有 `scoredConditionCount` 和完整归档保证可审计。
