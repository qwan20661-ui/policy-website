# 企业政策匹配打分规则说明

> 规则基线：2026-07-31
> 适用接口：`POST /api/pematching/match/enterprise`

## 1. 评分目标

系统只评价企业数据与政策规则要求的匹配程度。申报截止日期、企业注册地址推断、自然人主体、药械许可主体和技术转移机构等规则外信息不再阻断匹配。

必须区分：

1. `matchScore`：企业与政策规则的匹配分，用于排序。
2. `isRecommended`：匹配分达到60且没有硬性失败、没有不可计算规则。
3. `evidenceRatio`：真实企业证据覆盖率，不参与分数放大。

## 2. 模型与本地规则职责

模型只输出 `supported`、`contradicted`、`missing` 事实，负责字段映射、分支适用性、证据定位和候选值标准化。本地规则引擎负责证据回读、语义兼容校验、单位换算、比较、条件分和总分。

模型不得计算10分、30分、60分、90分或政策总分。模型证据与政策事实类型不兼容时，服务端将其降级为 `missing` 并记录 `semantic_evidence_incompatible`。

## 3. 条件状态与分组

| 组类型 | 作用 |
|---|---|
| `hard` | 硬性门槛；明确不满足时条件0分并使政策最终分归零 |
| `soft` | 普通匹配条件；有数据但不满足时保留30分基础分 |
| `special_pass` | 真实证据命中的直通车；满足前提时最终分至少90 |

`not_applicable` 跳过且不进入分母；`unknown` 按缺失得10分；规则目标、单位或结构无法可靠计算时为 `not_evaluable`，不进入分母并阻止推荐。

## 4. 缺失数据10分

企业缺少字段或有效证据时：

```text
evalStatus = pass
score = 0.1
passSource = default_missing_assumed
enterpriseValue = null
```

缺失10分适用于数值、存在型、定性、未知分支和无规则表兜底路径。它不表示企业满足政策，也不计为真实企业证据。显式数值0是有效数据，不能按缺失处理。

## 5. 数值评分

### 5.1 下限型 `gte` / `gt`

普通或软性条件：

```text
score = min(1.0, 0.3 + enterpriseValue / targetValue)
```

例如要求超过50人、企业3人：`0.3 + 3/50 = 0.36`，即36分。

硬性条件不使用成长分：严格按操作符比较，满足得100分，不满足得0分并使政策最终分归零。`gt` 在企业值等于目标值时仍是不满足。

### 5.2 上限、等值和存在型

| 类型 | 普通/软性条件 | 硬性条件 |
|---|---|---|
| `lte` / `lt` | 满足100，超限30 | 满足100，超限0并归零 |
| `equals` | 相等100，不等30 | 相等100，不等0并归零 |
| `has_value` | 有值100，缺失10 | 有值100，缺失10 |

目标值为0时按操作符直接判断，不做除法。目标为负数、非数值或单位无法可靠换算时进入 `not_evaluable`。

## 6. 定性条件

| 模型事实 | 普通/软性条件 | 硬性条件 |
|---|---:|---:|
| `supported` | 100 | 100 |
| `contradicted` | 30 | 0并归零 |
| `missing` | 10 | 10 |

取消定性置信度二次加成。模型 `confidence` 只用于审计和提示；兼容字段 `coeff_C` 固定为 `1.0`。

## 7. A/B总分

A/B不再由规则表 `ruleKind` 直接决定最终权重。运行时证据分层算法将条件标记为 `A1_exact`、`A2_derived`、`B_supporting`、`U_missing`、`R_rejected`、`N_not_evaluable` 或 `S_skipped`；A1/A2为核验证据，B为辅助证据，U/R为未核验证据。规则表 `ruleKind` 仅作为提取阶段提示和审计字段。

```text
A = A1/A2核验证据条件算术平均（审计字段）
B = B辅助证据条件算术平均（审计字段）

A、B不再改变最终分；所有适用且可评分条件逐条同权：final = sum(condition_score) / count(condition_score)
只有A：final = A
只有B：final = B
```

`skipped`、`not_evaluable` 和直通车条件不进入普通A/B分母。硬性失败时最终分为0。

## 8. 推荐与直通车

```text
isRecommended =
    hard_pass
    and pendingConditionCount == 0
    and final_score >= 0.6
```

全缺失政策最终为10分，不推荐。部分条件缺失不会自动成为待确认；若其他真实条件足够高，总分仍可能达到60。

直通车只有真实企业证据命中时才能触发，缺失10分和科技型中小企业缺失补足不能触发。直通车不能绕过硬性失败或 `not_evaluable`。

## 9. 科技型中小企业评价

继续使用官方分档计算科技人员、研发投入和科技成果三个维度。条件分为评价总分除以100，不套普通下限型30分基础加比例公式。

| 数据情况 | 处理 |
|---|---|
| 三个维度齐全 | 按官方分档直接相加 |
| 部分维度缺失 | 已核验得分 + 缺失维度满分的10% |
| 三个维度全缺失 | 评价总分为 `null`，条件级得10分 |

部分补足来源为 `tech_sme_evaluation_partial_assumed`，不计入真实证据覆盖率。

## 10. API字段一致性

| 字段 | 语义 |
|---|---|
| `matchScore` | 百分制规则匹配分 |
| `isRecommended` | 达到60且无硬性失败、无不可计算规则 |
| `matchStatus` | 正常为 `matched`；模型重试耗尽为 `匹配失败待重试` |
| `recommendationBlockers` | 兼容字段，正常结果为空数组 |
| `assumedConditionCount` | 缺失10分条件数量 |
| `evidenceRatio` | 真实企业证据条件数除以参与计分条件数 |
| `hasEnterpriseEvidence` | 缺失10分和专项缺失补足必须为 `false` |

## 11. 维护要求

修改评分时必须同时检查规则表路径、无规则表兜底路径、API轻量响应、完整归档、Excel解释和定向测试。不得重新引入缺失70分、缺失半权、1.5倍成长性公式、定性置信度加分或规则外资格阻断。
