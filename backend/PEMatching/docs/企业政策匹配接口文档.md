# 企业政策匹配接口文档

## 1. 接口说明

该接口接收政策推荐企业分页接口中的一条企业原始记录，使用 PEMatching 的企业字段标准化、结构化政策加载、规则表语义证据提取（适用时）和本地评分链路，返回该企业对应的政策匹配结果。

- 上游企业接口：`GET http://112.48.19.225:8500/cms/tb-base-business-info/web/page?pageNum=1&pageSize=100`
- 本接口请求体：上游响应 `data.list[]` 中的一条对象
- 匹配政策范围：默认加载结构化政策服务当前可获取的全部主政策；带 `RULE_TABLE_JSON` 的政策会启用模型语义证据提取，其他已结构化政策仍按本地结构化条件评分
- 计分口径：所有适用且可评分条件逐条同权平均；运行时证据层级只用于审计和展示，不再按规则表 `ruleKind` 使用固定70%/30%加权
- 执行方式：同步执行；政策数量多或模型响应较慢时，调用方应配置足够长的读取超时
- 结果保存：每次单企业推荐均在服务端归档完整跑数 JSON，并写入达梦轻量运行索引；两者均成功后才返回 HTTP 成功响应
- 对接边界：本接口不会主动请求上游企业分页接口；调用方应先从上游取得 `data.list[]` 的一条记录，再将该对象作为请求体提交

## 2. 请求地址

```http
POST http://<根服务地址>:3000/api/pematching/match/enterprise
Content-Type: application/json
```

`3000` 是统一公开入口，根服务会将匹配请求转发给内部 PEMatching `8010` 服务；调用方不应直接依赖 `8010` 地址。

## 3. 请求参数

### 3.1 请求体

请求体直接使用上游企业分页接口 `data.list[]` 中的一条企业对象，不需要再包装为数组。

必须满足：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 上游企业分页接口返回的企业 ID；兼容字段名 `enterpriseId`，用于结果入库和后续查询 |
| `enterpriseName` | 是 | 企业名称，用于识别企业和组织返回结果 |
| `creditCode` | 否 | 统一社会信用代码；提供后会写入内部跑数明细，未提供不影响匹配 |
| `operationInfoList` | 否 | 多年度经营数据；服务取 `year` 最大（同年取 `updateTime` 最新）的一条，金额按上游接口的“元”转换为内部“万元” |
| `mainTechnologyList` | 否 | 知识产权和技术信息 |
| `mainProductList` | 否 | 产品信息 |
| `honorQualificationList` | 否 | 荣誉和资质信息 |

请求示例：

接口也兼容以下包装形式，但推荐直接传企业对象。`id`（或 `enterpriseId`）和 `enterpriseName` 必填，其他企业字段均为可选；字段缺失时遵循既有的“待确认/默认假定”评分口径：

```json
{

```

### 3.2 查询参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `policyId` | 否 | 空 | 指定主政策 `fusionPolicyId`；可重复传入多个 |
| `fusionPolicyId` | 否 | 空 | `policyId` 的兼容名称 |
| `policyKeyword` | 否 | 空 | 按政策标题关键词过滤 |
| `policyLimit` | 否 | `0` | 最大匹配政策数；必须为非负整数，`0` 表示不额外限制 |
| `includeDocumentContent` | 否 | `false` | 是否在服务端加载政策全文。不会增加 HTTP 响应中的 `documents` 字段内容，但会增加上游读取、模型处理和归档体积，通常保持 `false` |

仅上述四类查询参数会被本接口解析。`reviewStatus`、`structureReviewStatus` 是其他政策目录接口的参数，传给本接口不会参与筛选。

筛选顺序为：先按 `policyId`（或兼容参数 `fusionPolicyId`）筛选，再按 `policyKeyword` 筛选，最后按 `policyLimit` 截断。若同时传入 `policyId` 与 `fusionPolicyId`，以 `policyId` 为准。

指定一条政策：

```http
POST /api/pematching/match/enterprise?policyId=6617
```

指定多条政策：

```http
POST /api/pematching/match/enterprise?policyId=6617&policyId=6652
```

### 4.1 政策匹配结果字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `fusionPolicyId` | string | 主政策 ID |
| `matchScore` | number / `null` | 百分制匹配分（`0` 至 `100`）；`null` 仅表示本条匹配未完成，不能按 0 分理解 |
| `level` | integer / `null` | 匹配星级：`0` 表示不匹配（`0` 至 `1` 分），`1` 表示 `(1, 40]` 分，`2` 表示 `(40, 60]` 分，`3` 表示 `(60, 70]` 分，`4` 表示 `(70, 90]` 分，`5` 表示 `(90, 100]` 分；`matchScore` 为 `null` 时本字段也为 `null` |
| `isRecommended` | boolean / `null` | 规则匹配推荐结论：无硬性失败、无不可计算规则且分数达到60分；不包含申报日期、地域或主体等规则外资格判断；`null` 表示本条未完成 |
| `evidenceRatio` | number / `null` | 已有真实企业证据支撑的参与计分条件占比，范围 `0` 至 `1`；与分数正交，用于同分排序和证据提示 |
| `confidenceLevel` | string / `null` | 证据置信度：`high`（覆盖率 ≥ 0.6）、`medium`（≥ 0.3）、`low`（< 0.3） |
| `verifiedConditionCount` | integer / `null` | 已核验且有真实企业证据的参与计分条件数 |
| `assumedConditionCount` | integer / `null` | 因企业字段缺失按默认口径计分的条件数；不等同于企业已经满足该条件 |
| `scoredConditionCount` | integer / `null` | 参与计分的条件总数 |
| `recommendationBlockers` | string[] | 兼容字段；正常完成的规则匹配固定为空数组 |
| `matchedConditions` | object[] | 仅包含 `evalStatus=pass` 的条件，用于展示“政策要求—企业数据—证据” |
| `matchedConditions[].hasEnterpriseEvidence` | boolean | `true` 表示本条件存在真实企业证据；缺失默认通过、`R_rejected`和其他未核验证据即使有展示值也为 `false`；模型证据被拒绝但本地标准字段可独立核验时按本地事实重新分层 |
| `matchedConditions[].evidence` | object[] | 证据数组，元素为 `sourcePath`（企业原始数据路径）和 `sourceText`（证据文本）；模型证据为空但本地标准字段或派生公式已核验时，服务端回填 `$normalized...` 证据 |
| `matchedConditions[].evidenceTier` | string | 运行时证据层级：`A1_exact`、`A2_derived`、`B_supporting`、`U_missing`、`R_rejected`、`N_not_evaluable` 或 `S_skipped`；历史归档可能为空 |
| `matchedConditions[].scoreBucket` | string | 兼容字段：`verified`、`supporting`、`unverified` 或 `excluded`；不再读取规则表 `ruleKind` 决定总分 |
| `matchedConditions[].bucketReason` | string | 服务端确定性证据分层原因；语义错配时记录拒绝类别 |
| `documents` | object[] | 关联文档列表；每项为 `{ id, policyTitle, fileName, filePath, policyAttribute, sourcePolicyId }`，`id`/`filePath` 可用于查看原文，`policyAttribute` 用于按类型分组 |
| `matchStatus` | string | 正常完成为 `matched`；模型重试耗尽时为 `匹配失败待重试` |
| `retryable` | boolean | 是否可在修复模型或网络问题后重试该条政策 |

其余政策展示字段 `applicationStartTime`、`applicationEndTime`、`mainFileTitle`、`issuingDepartment`、`maxAmount`、`documents`、`applicableScope`、`industryField`、`industryFieldPath`、`supportMethods` 均可能为空字符串或空数组，调用方应按政策源数据缺失处理。

### 4.2 政策关联分与计算说明

每条政策通过独立的 `associationMatch` 返回企业特征与政策方向的关联结果。该结果不参与 `matchScore`、`isRecommended` 或默认排序，也不表示企业已经满足申报资格。

```json
{
  "associationMatch": {
    "score": 31,
    "level": "weak",
    "isAssociated": false,
    "status": "matched",
    "reasons": ["企业注册地在厦门市，与政策适用区域一致"],
    "calculation": {
      "formula": "Σ(维度权重×状态系数)÷有效维度权重合计×100",
      "expression": "31.0÷100.0×100=31.0",
      "weightedContribution": 31.0,
      "effectiveWeight": 100.0,
      "score": 31.0,
      "dimensions": [
        {
          "dimension": "region_park",
          "name": "注册区域与园区",
          "weight": 15,
          "status": "strong",
          "coefficient": 1.0,
          "rawContribution": 15.0,
          "normalizedContribution": 15.0,
          "includedInDenominator": true,
          "reason": "企业注册地在厦门市，与政策适用区域一致"
        }
      ],
      "note": "关联分仅表示企业特征与政策方向的关联程度，不表示企业满足申报条件。"
    }
  }
}
```

`rawContribution=weight×coefficient`；`normalizedContribution=rawContribution÷effectiveWeight×100`。`strong/medium/weak/conflict/unknown` 的系数分别为 `1/0.7/0.4/0/0` 并进入有效权重，`not_applicable` 不进入分母。模型未启用或关联计算待重试时，计算字段保持稳定，但数值为 `null`、维度数组为空。

#### 维度计分与页面复算

`associationMatch.score` 是独立于 `matchScore` 的企业特征-政策方向关联分。查看器在“政策关联分”区块展示 `associationMatch.calculation.dimensions`：每一行对应一个维度，可据此复算关联分。服务端总分先按未截断的分子和分母计算并保留两位小数；逐行 `normalizedContribution` 也分别保留两位小数，逐行求和在极少数小数场景可能与总分相差 `0.01`，以 `calculation.expression` 和 `calculation.score` 为准。它不改变申报条件的逐项得分、推荐结论或默认排序。

固定维度权重如下：

| `dimension` | 页面名称 | 权重 |
|---|---|---:|
| `industry` | 所属行业 | 20 |
| `scale` | 企业规模 | 15 |
| `lifecycle_qualification` | 成立阶段与资质进阶 | 15 |
| `research_development` | 研发状态 | 15 |
| `employment` | 用工与就业 | 10 |
| `region_park` | 注册区域与园区 | 15 |
| `education_talent` | 学历与高层次人才 | 10 |

状态系数由服务端固定计算，不采纳模型自行给出的数值：

| `status` | 页面状态 | `coefficient` | 是否进入有效权重 |
|---|---|---:|---|
| `strong` | 强关联 | 1.0 | 是 |
| `medium` | 中关联 | 0.7 | 是 |
| `weak` | 弱关联 | 0.4 | 是 |
| `conflict` | 冲突 | 0 | 是 |
| `unknown` | 未知 | 0 | 是 |
| `not_applicable` | 不适用 | `null` | 否 |

对每一个进入分母的维度 `i`：

```text
rawContribution_i = weight_i × coefficient_i
effectiveWeight = Σ weight_i（仅计算 coefficient 非 null 的维度）
normalizedContribution_i = rawContribution_i ÷ effectiveWeight × 100
associationMatch.score = Σ rawContribution_i ÷ effectiveWeight × 100
```

例如，某次结果的有效权重为 `100`：所属行业为中关联（`20 × 0.7 = 14`），注册区域与园区为强关联（`15 × 1 = 15`），用工与就业为弱关联（`10 × 0.4 = 4`）。三行在查看器的“原始贡献”分别为 `14`、`15`、`4`，对应“归一化贡献（分）”分别为 `14`、`15`、`4`；其余维度按同一规则计算。总关联分由所有原始贡献之和除以有效权重后乘以 `100` 得到。

`not_applicable` 表示政策在该维度没有适用条件，既不加分也不扣分，并且从 `effectiveWeight` 中排除；`unknown` 表示当前无法可靠判定，贡献为 `0` 但仍保留在分母中，因此会降低关联分。只有至少一个 `strong`、`medium`、`weak` 或 `conflict` 维度，且有效权重大于 `0` 时，服务端才返回数值关联分；全部未知或不适用时 `associationMatch.score=null`，不能按 0 分理解。

查看器表格中的“进入分母”直接对应 `includedInDenominator`，不会根据显示分数自行推断；“判定理由”来自服务端经证据校验后的简短结论。完整企业/政策证据、模型输入输出和拒绝原因仍只保存在 `runId` 归档中。

`matchScore` 为 `null` 表示本次政策匹配未能完成，不能按 0 分理解。模型超时的政策仍保留在结果中，并标记：

```json
{
  "matchScore": null,
  "level": null,
  "isRecommended": null,
  "matchStatus": "匹配失败待重试",
  "retryable": true
}
```

### 4.3 完整跑数明细归档

为兼顾外部接口稳定性与后续排查，每次成功运行都会保存一份完整 JSON（包括请求筛选条件、政策完整输入、标准化企业快照、逐政策逐条件得分、风险提示及模型异常信息）。归档目录默认是：

```text
backend/PEMatching/output/enterprise_match_details/
```

可通过环境变量 `PEMATCHING_ENTERPRISE_MATCH_DETAIL_DIR` 覆盖目录。完整明细只保存在该文件归档中，不再写入达梦；达梦表 `SYSDBA.PEM_ENTERPRISE_MATCH_RUN` 只保存轻量 `data.policies` 对应的 `RESPONSE_JSON`、企业与运行元数据，以及用于关联归档的 `DETAIL_FILE_NAME`、`DETAIL_FILE_SIZE`。响应只提供 `meta.runId`，不返回服务器绝对路径或完整明细；文件归档或数据库写入任一失败时接口返回 `500`，不会返回没有可追溯结果的成功响应。

## 5. 查询企业最新匹配结果

```http
GET http://<根服务地址>:3000/api/pematching/match/enterprise?enterpriseId=900
```

`enterpriseId` 必填。接口按达梦入库时间倒序查询该企业最新一次成功结果，并返回与匹配接口相同的 `data.policies`。没有结果时仍返回 HTTP `200`、空政策数组和 `meta.found=false`；数据库异常或已存 JSON 无法解析时返回 `500`。完整明细文件不通过该接口返回。

## 6. 查询已有匹配结果的企业列表

```http
GET http://<根服务地址>:3000/api/pematching/match/enterprises?page=1&size=20&enterpriseName=厦门
```

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `page` | 否 | `1` | 当前页，兼容 `pageNum`、`pageNumber` |
| `size` | 否 | `20` | 每页数量，范围 `1` 至 `100`，兼容 `pageSize` |
| `enterpriseName` | 否 | 空 | 企业名称包含搜索 |

同一企业多次运行时，列表按企业 ID 去重，只返回最新一次运行的企业名称、信用代码、`latestRunId`、`policyCount` 和 `latestMatchedAt`。列表不会读取或返回 `RESPONSE_JSON` CLOB，也不会读取完整明细文件，`pagination.total` 表示已有结果的去重企业数。

## 7. 失败响应

### 企业请求体格式错误

HTTP 状态码：`400`

```json
{
  "success": false,
  "message": "企业信息格式错误：必须提供 id 或 enterpriseId。"
}
```

### 未找到符合条件的结构化主政策

HTTP 状态码：`400`

```json
{
  "success": false,
  "message": "未找到符合条件的结构化主政策。"
}
```

### 查询参数格式错误

HTTP 状态码：`400`

```json
{
  "success": false,
```

### 8.1 企业测试目录批跑

HTTP 接口一次只接收一家企业的 JSON 对象，不能把目录路径或 `tech_sme_enterprises.json` 这类包含 `enterprises[]` 的聚合对象直接作为请求体。批量处理 `backend/PEMatching/企业测试目录` 时使用目录批跑器：

```powershell
python backend\PEMatching\run_enterprise_test_directory.py `
  --input-dir backend\PEMatching\企业测试目录 `
  --limit 3
```

批跑器默认调用 `http://127.0.0.1:3000/api/pematching/match/enterprise`，默认文件名规则为 `^\d{4}_.*\.json$`，只提交四位序号开头的单企业 JSON，并在请求前校验 `id`（或 `enterpriseId`）和 `enterpriseName`。确认三家企业响应及数据库入库正常后，去掉 `--limit 3` 执行全量；需要续跑时使用原 `--run-dir` 并增加 `--resume`。

## 9. 评分与推荐口径

| 场景 | `matchScore` | `isRecommended` |
|---|---|---|
| 企业有真实证据且满足普通规则 | 条件通常为100分，所有适用且可评分条件逐条同权平均 | 最终分达到60且无硬性失败、无不可计算规则时为 `true` |
| 企业有数据但普通下限尚未达标 | `min(100, 30 + 100 × 企业值 ÷ 目标值)`；例如3人对50人要求为36分 | 根据最终聚合分判断 |
| 企业字段缺失或指定年度无同年度数据 | 不虚构企业事实；该条件记10分，计入 `assumedConditionCount`，不计为真实证据 | 全部缺失时最终10分，不推荐；部分缺失时由最终聚合分决定 |
| 普通上限或等值规则不满足 | 条件记30分 | 根据最终聚合分判断 |
| 硬性条件明确不满足 | 条件及政策最终分归零 | `false` |
| 模型超时、连接失败且重试耗尽 | `null`，不与普通低分混排 | `null`，`matchStatus` 为“匹配失败待重试”且 `retryable=true` |

`isRecommended` 只表示企业数据与政策规则的评分结果，不是完整申报资格结论。接口不再使用申报截止日期、行政区推断、自然人主体、药械许可主体或技术转移机构等规则外信息阻断推荐；调用方仍应结合政策原文、申报窗口和材料清单进行业务复核。
