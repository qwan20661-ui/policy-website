# 企业政策双链路匹配优化实施计划

## 1. 目标与边界

系统保留现有申报要求匹配链路，并新增完全独立的企业-政策关联匹配链路。同一政策同时返回原 `matchScore` 和新增 `associationMatch.score`，两者不加权、不相加、不互相修正。

| 保护项 | 约束 |
|---|---|
| 企业输入 | 不修改 `POST /api/pematching/match/enterprise` 请求体，不新增必填字段 |
| 企业标准化 | 不调整金额、比例、人数、资质、行业和地区的现有标准化语义 |
| 原评分 | 不修改条件事实、硬性失败、缺失分、直通车、`final_score` 和 `isRecommended` |
| 原排序 | 继续按原匹配分及证据覆盖率排序，关联分不参与默认排序 |
| 失败隔离 | 关联模型失败只影响 `associationMatch`，不使原匹配结果失败 |

## 2. 两阶段执行

```text
现有企业对象 -> 全部政策申报条件匹配 -> 原分数和推荐结论
             -> 全部政策关联匹配     -> associationMatch
             -> 按 fusionPolicyId 合并，继续使用原排序
```

两个阶段严格串行，分别使用同一个 `MAX_WORKERS` 上限，避免关联请求与原语义请求叠加后超过模型容量。关联服务使用企业和政策对象的独立副本，只读取既有字段。

## 3. 关联维度与计分

| 维度 | 权重 | 主要事实 |
|---|---:|---|
| `industry` | 20 | 行业、产品、服务和高新技术领域 |
| `scale` | 15 | 企业规模、人数、营收和资产 |
| `lifecycle_qualification` | 15 | 成立阶段、注册类型、现有资质及合理进阶 |
| `research_development` | 15 | 研发费用、研发人员、研发机构、研发科目和知识产权 |
| `employment` | 10 | 员工、新增就业、高校毕业生、培训和社保 |
| `region_park` | 15 | 行政区、火炬高新区、自贸区及其他园区 |
| `education_talent` | 10 | 学历、职称、博士后和高层次人才 |

模型每个维度只能返回 `strong`、`medium`、`weak`、`conflict`、`unknown` 或 `not_applicable`。本地系数依次为 `1.0`、`0.7`、`0.4`、`0`、`0`，`not_applicable` 不进入分母。

```text
associationScore = Σ(有效维度权重 × 状态系数) / Σ(非 not_applicable 权重) × 100
```

模型必须同时引用可回读的企业证据和政策证据；伪造字段、无法回读的值、重复维度或非法状态统一降级为 `unknown`。从业人数不超过 300 人只能形成小微候选关联；无研发数据不等于无研发；博士人数不能证明博士后工作站；企业资质不能证明个人资质。

## 4. 输入、输出与归档

企业关联画像从现有企业对象和原始数据中选择行业、规模、注册、研发、人员、学历和资质字段，不发送信用代码、电话、邮箱和联系人。政策输入包含政策 ID、标题、摘要、发文部门、行业、适用范围、适用对象、申报要求、规则要求、支持方式和政策类型；结构化信息不足且当前政策对象已含正文时，正文摘录最多 3000 字。

公共接口仅新增：

```json
{
  "associationMatch": {
    "score": 86.0,
    "level": "strong",
    "isAssociated": true,
    "status": "matched",
    "reasons": ["企业行业与政策支持行业一致"],
    "calculation": {
      "formula": "Σ(维度权重×状态系数)÷有效维度权重合计×100",
      "expression": "86.0÷100.0×100=86.0",
      "weightedContribution": 86.0,
      "effectiveWeight": 100.0,
      "score": 86.0,
      "dimensions": []
    }
  }
}
```

公共 `calculation.dimensions` 返回七维权重、状态、系数、原始贡献、归一化贡献、是否进入分母和简短理由，用于前端复算；企业证据值、政策证据原文、证据拒绝原因、模型输入输出、耗时和 token 仍只保存在现有 `runId` 完整归档中。未启用时返回 `status=disabled`；重试耗尽时返回 `status=待重试`、`score=null`，不得按零关联处理。

## 5. 配置、测试与验收

关联链路由 `POLICY_ASSOCIATION_LLM_ENABLED` 独立启停。上线前使用固定企业和全政策快照验证总耗时、请求数、超时率和 token，再设置为 `true`。

验收必须覆盖固定权重、证据校验、输入不可变、原结果字段逐项不变、原排序不变、同名不同 ID 政策、无规则表政策、单政策关联失败、公共响应精简和 `runId` 完整归档。除新增 `associationMatch` 外，开启和关闭关联层时原 `matchScore`、`isRecommended`、条件详情和排序结果必须一致。
