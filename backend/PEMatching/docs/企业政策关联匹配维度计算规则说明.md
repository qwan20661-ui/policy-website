# 企业政策关联匹配维度计算规则说明

## 1. 适用范围

本文说明 `associationMatch` 的维度评分规则，适用于企业政策匹配接口返回的：

```text
data.policies[].associationMatch
```

关联分用于衡量企业特征与政策支持方向的关联程度。它与申报条件匹配分 `matchScore` 完全独立：

| 分数 | 用途 | 是否表示已满足申报条件 |
|---|---|---|
| `matchScore` | 根据结构化申报条件及企业事实计算的匹配/召回分 | 否，仍需核验每条条件的企业证据和状态 |
| `associationMatch.score` | 根据行业、规模、研发、区域等特征计算的关联分 | 否，只表示政策方向关联程度 |

关联分不改变 `matchScore`、`isRecommended`、申报条件明细或默认排序。

## 2. 计算链路

```text
企业标准画像 + 政策摘要
        ↓
关联模型返回每个维度的状态和双侧证据引用
        ↓
服务端校验证据、维度名称和状态合法性
        ↓
服务端按固定状态系数和固定维度权重计算贡献
        ↓
返回 associationMatch.score、calculation 和 dimensions
```

模型不直接决定分数。模型只输出维度状态；服务端使用固定表将状态映射为状态系数，再计算最终分数。

## 3. 主政策信息输入范围

关联链路对每个融合主政策调用 `build_policy_association_profile()`，构造只读、有界的 `policyProfile`。关联模型使用的是下表字段，而不是主政策的完整数据库行、附件全文或既有申报条件匹配结果。

| `policyProfile` 字段 | 主政策信息来源 | 用途 |
|---|---|---|
| `policyId` | `id`，为空时回退 `fusionPolicyId`、详情 `id` | 绑定模型返回结果；返回的政策 ID 不一致时，本次关联结果直接失败 |
| `title` | 主政策 `title`，为空时回退 `policyInfo.policyTitle`、`mainFileTitle` | 识别政策主题 |
| `summary` | `policyInfo.summary` | 概括政策支持方向，最长 3000 字符 |
| `issuingDepartment` | 详情 `issuingDepartment`，为空时回退 `policyInfo.issuingDepartment` | 辅助判断政策主体和发布来源 |
| `industryField` / `industryFieldPath` | `policyInfo` 行业领域及路径 | 对应所属行业维度 |
| `applicableScope` | 详情 `applicableScope`，为空时回退 `policyInfo.applicableScope` | 对应注册区域与园区等地域维度 |
| `applicableTargets` | 详情 `conditions[].applicableTarget` | 判断政策面向的企业对象 |
| `applicationRequirements` | 详情 `conditions[].applicationRequirement`，以及结构化条件的 `政策原文` / `政策要求` | 提取与规模、研发、就业、人才等有关的主要条件 |
| `ruleRequirements` | `ruleTableJson` / `rule_table_json` 中递归提取的规则文本片段 | 补充结构化规则中的可读要求 |
| `supportMethods` | 详情 `supportMethods[].contentDesc` 或主政策 `support_methods` | 识别资金奖励、服务支持等政策支持方式 |
| `policyTypes` | 关联文档的 `policyTitle`、`title`、`name` 或 `fileName` | 识别政策文件类型和主题 |
| `documentExcerpt` | 仅在核心政策信息不足两类时，使用加载器预先生成的清洗、限长摘录 | 为信息不足的政策提供受控补充上下文 |

### 3.1 主政策输入边界

- `applicableTargets`、`applicationRequirements`、`ruleRequirements`、`supportMethods` 和 `policyTypes` 会去重，最多保留 80 项，每项最多 1200 字符。
- `documentExcerpt` 仅在 `summary`、`industryField`、`applicableScope`、适用对象、申报要求这五类核心信息中不足两类时启用；合并后的摘录最多 3000 字符。
- 不默认发送 `documents[].content`、附件全文、申报材料全文、模型历史输入输出或完整企业-政策匹配归档。
- `documentExcerpt` 只能来自加载器生成的清洗限长摘录，不能回退为附件原文。
- 关联链路使用政策对象的深拷贝，只读构造摘要，不会修改主政策数据或原有申报条件匹配链路。

因此，关联分是基于“主政策摘要 + 结构化申报要求/规则片段”的方向性判断；若需要审计完整原文、附件或模型证据，应通过对应 `runId` 完整归档查看，而不是将这些内容扩展到公共关联评分响应。

### 3.2 维度证据不得串用

每个维度的得分只能由其自身语义范围内的企业和政策事实支撑。服务端除校验证据字段和值能否回读外，还会校验字段是否属于当前维度：

- 企业注册地、所在省市区、园区，以及政策 `applicableScope`，只能用于 `region_park`。
- 企业规模、营收、资产、员工人数只能用于 `scale` 或 `employment`；其中员工人数不能单独证明营收、资产或法定小微企业资格。
- 因此，“企业在厦门，政策适用于厦门”只能为地域园区维度提供关联证据，不能让企业规模维度获得弱关联或其他分数。
- 若模型将地域证据用于企业规模等无关维度，服务端会把该维度降级为 `unknown`，记录“字段不属于当前维度”，并按未知状态的 0 系数计入该维度分母。

## 4. 固定维度权重

| `dimension` | 页面名称 | 权重 | 主要判断事实 |
|---|---|---:|---|
| `industry` | 所属行业 | 20 | 行业、产品、服务及高新技术领域 |
| `scale` | 企业规模 | 15 | 人数、营收、资产及企业规模 |
| `lifecycle_qualification` | 成立阶段与资质进阶 | 15 | 成立阶段、注册类型、已有资质及合理进阶 |
| `research_development` | 研发状态 | 15 | 研发费用、研发人员、研发机构、研发科目及知识产权 |
| `employment` | 用工与就业 | 10 | 员工、新增就业、高校毕业生、培训及社保 |
| `region_park` | 注册区域与园区 | 15 | 行政区、火炬高新区、自贸区及其他园区 |
| `education_talent` | 学历与高层次人才 | 10 | 学历、职称、博士后及高层次人才 |

全部维度适用时，权重合计为 `100`。实际计算时，`not_applicable` 维度会从有效权重中排除，因此有效权重不一定等于 100。

## 5. 状态系数来源

服务端只接受下表中的状态，并按固定映射赋予 `coefficient`：

| `status` | 页面状态 | `coefficient` | 是否进入分母 | 结果含义 |
|---|---|---:|---|---|
| `strong` | 强关联 | 1.0 | 是 | 获得该维度全部权重 |
| `medium` | 中关联 | 0.7 | 是 | 获得该维度 70% 权重 |
| `weak` | 弱关联 | 0.4 | 是 | 获得该维度 40% 权重 |
| `conflict` | 冲突 | 0 | 是 | 明确不一致，贡献为 0，仍占有效权重 |
| `unknown` | 未知 | 0 | 是 | 当前无法可靠判断，贡献为 0，仍占有效权重 |
| `not_applicable` | 不适用 | `null` | 否 | 政策不涉及该维度，完全排除 |

状态系数由 `backend/PEMatching/service/policy_association_service.py` 中的 `STATUS_COEFFICIENTS` 固定定义，不接收模型自行给出的数值。

### 5.1 服务端降级规则

以下情况会被服务端降级为 `unknown`，因此状态系数为 `0` 且仍进入有效权重：

- 返回重复的维度。
- 返回未支持的维度状态。
- 未提供可回读的企业侧证据。
- 未提供可回读的政策侧证据。
- 企业或政策证据字段、路径或值未通过本地校验。

这使模型的文字结论不能绕过服务端的证据约束。

## 6. 分子、分母和贡献计算

对于每个维度 `i`：

```text
rawContribution_i = weight_i × coefficient_i

effectiveWeight = Σ weight_i
                  仅统计 coefficient_i 非 null 的维度

normalizedContribution_i = rawContribution_i ÷ effectiveWeight × 100

associationMatch.score = Σ rawContribution_i ÷ effectiveWeight × 100
```

字段对应关系如下：

| 接口字段 | 计算含义 |
|---|---|
| `dimensions[].weight` | 维度的固定基础权重 |
| `dimensions[].coefficient` | 由最终 `status` 映射出的固定系数 |
| `dimensions[].rawContribution` | `weight × coefficient`，即该维度进入总分分子的值 |
| `dimensions[].includedInDenominator` | `coefficient` 是否非 `null`；为 `true` 时，该维度权重进入有效权重 |
| `dimensions[].normalizedContribution` | `rawContribution ÷ effectiveWeight × 100`，即页面显示的维度贡献分 |
| `calculation.weightedContribution` | 所有 `rawContribution` 的合计，即总分分子 |
| `calculation.effectiveWeight` | 所有进入分母维度的权重合计 |
| `calculation.expression` | 服务端记录的本次总分计算式 |
| `calculation.score` / `associationMatch.score` | 最终关联分，百分制 |

## 7. 完整示例

设一次关联判断得到以下维度状态：

| 维度 | 权重 | 状态 | 系数 | 原始贡献 | 进入分母 |
|---|---:|---|---:|---:|---|
| 所属行业 | 20 | `medium` | 0.7 | `20 × 0.7 = 14` | 是 |
| 企业规模 | 15 | `unknown` | 0 | `15 × 0 = 0` | 是 |
| 成立阶段与资质进阶 | 15 | `not_applicable` | `null` | 不计算 | 否 |
| 研发状态 | 15 | `strong` | 1.0 | `15 × 1 = 15` | 是 |
| 用工与就业 | 10 | `weak` | 0.4 | `10 × 0.4 = 4` | 是 |
| 注册区域与园区 | 15 | `conflict` | 0 | `15 × 0 = 0` | 是 |
| 学历与高层次人才 | 10 | `not_applicable` | `null` | 不计算 | 否 |

计算过程：

```text
weightedContribution = 14 + 0 + 15 + 4 + 0 = 33

effectiveWeight = 20 + 15 + 15 + 10 + 15 = 75

associationMatch.score = 33 ÷ 75 × 100 = 44.00
```

页面中的归一化贡献为：

| 维度 | 归一化贡献（分） |
|---|---:|
| 所属行业 | `14 ÷ 75 × 100 = 18.67` |
| 企业规模 | `0 ÷ 75 × 100 = 0` |
| 研发状态 | `15 ÷ 75 × 100 = 20` |
| 用工与就业 | `4 ÷ 75 × 100 = 5.33` |
| 注册区域与园区 | `0 ÷ 75 × 100 = 0` |
| 合计 | `44.00` |

`unknown` 和 `conflict` 都是 0 分，但它们仍进入分母，因此会降低总分；两个 `not_applicable` 维度完全不影响此次总分。

## 8. 空分、等级和关联结论

服务端仅在以下条件同时满足时返回数值关联分：

- 有至少一个 `strong`、`medium`、`weak` 或 `conflict` 维度。
- `effectiveWeight` 大于 0。

若全部维度均为 `unknown` 或 `not_applicable`，则：

```text
associationMatch.score = null
associationMatch.level = unknown
associationMatch.isAssociated = null
```

`null` 表示没有足够的有效关联信息，不能解释为 0 分。

数值关联分的等级和结论口径：

| 分数范围 | `level` | `isAssociated` |
|---:|---|---|
| `80 - 100` | `strong` | `true` |
| `60 - 79.99` | `medium` | `true` |
| `30 - 59.99` | `weak` | `false` |
| `0 - 29.99` | `none` | `false` |

## 9. 精度与查看器口径

服务端按未截断的 `weightedContribution ÷ effectiveWeight × 100` 计算最终分数，并将 `associationMatch.score` 保留两位小数。每条 `normalizedContribution` 也独立保留两位小数，因此在少数循环小数场景，逐行显示值相加可能与总分相差 `0.01`。

查看器应按以下优先级展示和核验：

1. 总分以 `calculation.expression` 和 `calculation.score` 为准。
2. 每条维度分以 `normalizedContribution` 展示，用于解释分数来源。
3. “进入分母”直接读取 `includedInDenominator`，不根据得分是否为 0 推断。
4. “判定理由”读取 `reason`；完整企业/政策证据、模型输入输出和拒绝原因仅保留在 `runId` 完整归档中。

## 10. 运行状态

| `associationMatch.status` | 含义 | 计算字段表现 |
|---|---|---|
| `matched` | 已完成关联判断 | 返回分数、公式和维度账目 |
| `disabled` | 关联链路未启用或未配置 | 分数为 `null`，维度数组为空 |
| `待重试` | 关联模型或协议失败且重试耗尽 | 分数为 `null`，维度数组为空；原申报条件匹配结果仍可正常使用 |
