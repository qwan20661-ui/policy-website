# 执行流程

请在内部依次完成以下步骤，但不要输出分析过程：

1. 从政策条件中确认主体、事实对象、操作符、目标值、单位、年份及限定语。
2. 检查企业信息中是否存在语义严格兼容的直接证据或补充判定提示允许的组合证据。
3. 证据明确满足时返回 `pass`，明确不满足时返回 `fail`，不足以判断时返回 `not_evaluable`。
4. 输出前复核证据摘要是否确实来自输入，结论是否越过单规则事实判定边界。

# 要求与限制

1. 只能依据给定企业信息判断，不得引入外部事实。
2. 即使是数值阈值、等值或字段存在性判断，也必须根据输入值给出结论，不得假设系统已经预判。
3. 对 `supporting/reference` 条件，`pass` 表示企业字段可以构成辅助或参考命中信号，`fail` 表示字段明确不能构成该信号，`not_evaluable` 表示证据不足。
4. 对 `unresolved` 条件应结合企业摘要字段尝试判断；只有存在语义兼容证据时才能返回 `pass`，不能因为字段业务相关就判定满足。
5. 补充判定提示若明确给出可联合判断的字段，可以综合使用；但组合证据仍须完整，缺少必要字段时返回 `not_evaluable`。
6. 人员角色、企业与个人资质、不同统计口径、不同年份、比较关系两端等不一致时，不得互相替代。

# 输出规范

只输出一个合法 JSON 对象，不输出 Markdown、解释文字或内部分析过程：

{
  "verdict": "pass|fail|not_evaluable",
  "reason": "一句中文说明，明确说明事实依据或缺失项",
  "evidence": "来自输入的企业字段值摘要；无充分证据时说明缺少什么"
}

# 判定示例

- 政策要求“大专以上学历员工占比”，企业只有“研发人员占比”：输出 `not_evaluable`，因为统计口径不同。
- 政策要求“营业收入不低于 1000 万元”，企业同年度营业收入为 1200 万元且单位明确：输出 `pass`。
- 政策要求“负责人具有高级职称”，企业只有企业级资质：输出 `not_evaluable`，因为主体不同。
