# 融合结构化详情页面 API 文档

---

## 一、概述

接口地址：http://127.0.0.1:33044

## 二、获取融合主政策列表

**接口地址：** `GET /api/fusion-classification/policies`

### 请求参数（Query）

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `page` | int | 是 | `1` | 页码，从 1 开始 |
| `size` | int | 是 | `20` | 每页条数（10 / 20 / 50） |
| `keyword` | string | 否 | - | 搜索关键词，匹配政策标题或关联文件名称 |
| `applicationStatus` | int | 否 | - | 申报状态：`0`=未开始，`1`=申报中，`2`=已结束 |
| `sceneUsage` | string | 否 | - | 场景用途筛选 |
| `applicableScope` | string | 否 | - | 政策范围/适用范围筛选 |

### 申报状态判定说明

`applicationStatus` 基于当前时间 `now` 与列表项 `applicationStartTime`、`applicationEndTime` 的关系进行判定：

| 传值 | 含义 | 判定规则 |
|------|------|----------|
| `0` | 未开始 | `now < applicationStartTime` |
| `1` | 申报中 | `applicationStartTime <= now <= applicationEndTime`；如果 `applicationStartTime` 和 `applicationEndTime` 都为空，也会一并返回 |
| `2` | 已结束 | `now > applicationEndTime` |

补充说明：

- 当 `applicationStatus=1` 时，接口会额外把“申报开始时间为空且申报结束时间为空”的政策视为可返回数据。
- 只有开始时间为空或只有结束时间为空，不命中这条补充规则，仍按正常日期区间逻辑判断。

### 响应参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 固定返回 `true` |
| `data` | array | 政策列表，每项见下表 |
| `pagination` | object | 分页信息 |

### data[] 每一项

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 政策唯一 ID |
| `directoryTitle` | string | 融合目录标题 |
| `policyTitle` | string | 政策标题 |
| `issuingDepartment` | string | 发文部门 |
| `sceneUsage` | string | 场景用途，如 `"产业扶持-科技创新-高企认定"` |
| `applicableScope` | string | 适用范围，如 `"厦门市"` |
| `applicationStartTime` | string | 申报开始时间，格式 `YYYY-MM-DD` |
| `applicationEndTime` | string | 申报结束时间，格式 `YYYY-MM-DD` |
| `maxAmount` | string | 最高奖励金额，如 `"500万元"` |
| `status` | string | 状态：`ACTIVE` 启用 / `INACTIVE` 停用 |
| `reviewStatus` | int | 主政策审核状态，来自 `X1_FUSION_POLICY.MARK_REVIEW_STATUS`：`0`=待审核，`1`=已通过 |
| `structureReviewStatus` | int | 结构化审核状态，来自 `X1_FUSION_POLICY.STRUCTURE_REVIEW_STATUS`：`0`=待审核，`1`=已通过 |
| `requireSourcePolicyId` | int | 可选开关，传 `1` 时仅返回 `X1_FUSION_POLICY.SOURCE_POLICY_ID` 非空的记录，结构页用于只展示主政策 |

> 结构页列表还支持 `structureReviewStatus` 作为筛选参数，取值可为 `all`、`1`/`已审核`、`0`/`未审核`。

### curl 调用示例

```bash
# 查询第1页，每页20条
curl --location 'http://127.0.0.1:33044/api/fusion-classification/policies?page=1&size=20'

# 按关键词搜索
curl -s "http://localhost/api/fusion-classification/policies?page=1&size=20&keyword=高新技术" | jq

# 查询当前申报中的政策
curl -s "http://localhost/api/fusion-classification/policies?page=1&size=20&applicationStatus=1" | jq

# 按场景用途和政策范围联合筛选
curl -s "http://localhost/api/fusion-classification/policies?page=1&size=20&sceneUsage=产业扶持-科技创新-高企认定&applicableScope=厦门市" | jq

```

## 三、查询主政策结构化信息

根据融合政策 ID 获取完整的结构化数据（基本信息、申报条件、支持方式、材料、关键词、关联文档等）。

**接口地址：** `GET /api/fusion-classification/fusion-detail`

### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `fusionPolicyId` | string | 是 | 融合政策 ID |

### 响应参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 固定返回 `true` |
| `data` | object | 结构化详情对象，结构见下表 |

### data 对象

| 参数 | 类型 | 说明 |
|------|------|------|
| `sourcePolicyId` | string | 源政策 ID |
| `reviewStatus` | string | 主政策审核状态（兼容字段） |
| `structureReviewStatus` | string | 结构化审核状态 |
| `structureReviewedAt` | string | 结构化审核时间 |
| `structureReviewedBy` | string | 结构化审核人 |
| `structureReviewRemark` | string | 结构化审核备注 |
| `policyInfo` | object | 基本信息（详见下方 policyInfo 表） |
| `documents` | array | 关联文档列表（详见下方 documents[] 表） |
| `keywords` | array | 政策关键词列表，每项 `{id, text}` |
| `conditions` | array | 申报条件列表（详见下方 conditions[] 表） |
| `supportMethods` | array | 支持方式列表（详见下方 supportMethods[] 表） |
| `materials` | array | 申报材料列表（详见下方 materials[] 表） |
| `attachments` | array | 附件列表，每项 `{id, name, attachmentId}` |

> 说明：为兼容现有前端的叶子值展示，原字段 `policyInfo.sceneUsage`、`policyInfo.applicableScope`、`policyInfo.industryField`、`keywords[].text`、`conditions[].applicableTarget`、`supportMethods[].supportType` 保持不变；同时新增 `policyInfo.sceneUsagePath`、`policyInfo.applicableScopePath`、`policyInfo.industryFieldPath`、`keywords[].pathText`、`conditions[].applicableTargetPath`、`supportMethods[].supportTypePath`，用于返回完整层级文本。

### data.policyInfo 基本信息

| 参数 | 类型 | 说明 |
|------|------|------|
| `policyTitle` | string | 政策标题 |
| `policyOriginalTitle` | string | 政策原标题 |
| `sceneUsage` | string | 场景用途，多个以分号分隔 |
| `applicableScope` | string | 适用范围，多个以分号分隔 |
| `industryField` | string | 行业领域，多个以分号分隔；二级分类保存为 `一级-二级`，只有一级分类时直接保存一级名称 |
| `issuingDepartment` | string | 发文部门 |
| `policyCode` | string | 政策文号 |
| `effectiveStartDate` | string | 有效开始时间，格式 `YYYY-MM-DD` |
| `effectiveEndDate` | string | 有效结束时间，格式 `YYYY-MM-DD` |
| `contactInfo` | string | 联系方式，多个以分号分隔 |
| `applicationVolume` | string | 申报量 |
| `summary` | string | 政策摘要 |

### data.documents[] 关联文档

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 关联文档 ID。读取正文时应使用这个 ID 调用下方“关联文档正文读取接口” |
| `sourcePolicyId` | string | 原始政策 ID |
| `policyTitle` | string | 文档政策标题 |
| `policyAttribute` | string | 政策属性，例如 `指导政策` / `实施细则` / `结果公告` / `申报通知` |
| `reviewStatus` | string | 文档审核状态，例如 `已通过` |
| `fileName` | string | 文档文件名 |
| `filePath` | string | 数据库中的相对文件路径，仅供后端定位源文件与排障使用，调用方不要直接把它当成可访问 URL |
| `fileSuffix` | string | 文件后缀，例如 `md` / `pdf` / `docx` |
| `displayOrder` | string | 显示顺序 |
| `publishDate` | string | 发布时间 |
| `documentNo` | string | 发文字号 |
| `issuingDepartment` | string | 发文部门 |
| `policyLevel` | string | 政策层级 |
| `originalUrl` | string | 原始来源链接，若抓取时有记录则返回 |

### 关联文档正文读取接口

说明：`GET /api/fusion-classification/fusion-detail` 返回的 `documents[].filePath` 是后端服务器上的文件相对路径，外部调用方通常无法直接访问。  
如果需要获取政策原文正文，请使用 `documents[].id` 再调用下面这个接口，而不是自行读取 `filePath`。

**接口地址：** `GET /api/fusion-classification/documents/content`

### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | `data.documents[].id` |

### 响应参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 是否成功 |
| `data.title` | string | 文档标题 |
| `data.filePath` | string | 数据库中的原始文件路径 |
| `data.content` | string | 文档正文内容。`md` 直接返回文本，其他类型由后端提取文本后返回 |

### 调用示例

```bash
# 第一步：先查结构化详情，拿到 documents[].id
curl --location 'http://127.0.0.1:33044/api/fusion-classification/fusion-detail?fusionPolicyId=1'

# 第二步：再用文档 ID 读取正文
curl --location 'http://127.0.0.1:33044/api/fusion-classification/documents/content?id=13802'
```

### data.conditions[] 申报条件

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 条件 ID |
| `applicableTarget` | string | 适用对象 |
| `applicationStartTime` | string | 申报开始时间，格式 `YYYY-MM-DD` |
| `applicationEndTime` | string | 申报结束时间，格式 `YYYY-MM-DD` |
| `announcementDate` | string | 公示时间，格式 `YYYY-MM-DD` |
| `applicationRequirement` | string | 申报要求，对接 `APPLICATION_CONDITION.APPLICATION_REQUIREMENT` |
| `applicationInstruction` | string | 申报说明，对接 `APPLICATION_CONDITION.PROMPT_CONTENT` |
| `cluster` | object | 结构化明细（工商基础 / 团队 / 知识产权等） |

### data.supportMethods[] 支持方式

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 支持方式 ID |
| `supportType` | string | 支持类型，如 `"资金奖励"` |
| `contentDesc` | string | 内容描述 |
| `amount` | string | 金额，如 `"30万元"` |
| `maxAmount` | string | 最高金额，如 `"500万元"` |

### data.materials[] 申报材料

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 材料 ID |
| `materials` | string | 申报材料描述 |
| `method` | string | 申报方式 |
| `url` | string | 申报链接 |

### curl 调用示例

```bash
curl --location 'http://127.0.0.1:33044/api/fusion-classification/fusion-detail?fusionPolicyId=1'
```

## 四、结构化审核接口

### 4.1 审核通过

**接口地址：** `POST /api/fusion-classification/structure/review/approve`

### 请求参数（JSON）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 融合主政策 ID |
| `reviewedBy` | string | 否 | 结构化审核人，不传则取当前登录用户 |
| `remark` | string | 否 | 结构化审核备注 |

### 4.2 撤销审核

**接口地址：** `POST /api/fusion-classification/structure/review/revoke`

### 请求参数（JSON）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 融合主政策 ID |
| `reviewedBy` | string | 否 | 操作人，不传则取当前登录用户 |
