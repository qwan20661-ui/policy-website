# 企业政策匹配接口文档

## 1. 接口说明

该接口接收政策推荐企业分页接口中的一条企业原始记录，使用 PEMatching 已有的企业字段标准化、规则表政策加载、模型语义证据提取和本地评分链路，返回该企业对应的政策匹配结果。

- 上游企业接口：`GET http://112.48.19.225:8500/cms/tb-base-business-info/web/page?pageNum=1&pageSize=100`
- 本接口请求体：上游响应 `data.list[]` 中的一条对象
- 匹配政策范围：默认匹配全部已经生成 `RULE_TABLE_JSON` 的主政策
- 执行方式：同步执行；政策数量多或模型响应较慢时，调用方应配置足够长的读取超时
- 文件输出：每次单企业推荐均在服务端归档完整跑数 JSON；HTTP 响应仅返回企业画像页面所需的轻量字段

## 2. 请求地址

```http
POST http://<PEMatching服务地址>:8010/api/pematching/match/enterprise
Content-Type: application/json
```

## 3. 请求参数

### 3.1 请求体

请求体直接使用上游企业分页接口 `data.list[]` 中的一条企业对象，不需要再包装为数组。

必须满足：

| 字段 | 必填 | 说明 |
|---|---|---|
| `enterpriseName` | 是 | 企业名称，用于识别企业和组织返回结果 |
| `creditCode` | 否 | 统一社会信用代码；提供后会写入内部跑数明细，未提供不影响匹配 |
| `operationInfoList` | 否 | 多年度经营数据；金额按上游接口的“元”转换为内部“万元” |
| `mainTechnologyList` | 否 | 知识产权和技术信息 |
| `mainProductList` | 否 | 产品信息 |
| `honorQualificationList` | 否 | 荣誉和资质信息 |

请求示例：

```json
{
  "id": "900",
  "enterpriseName": "厦门示例科技有限公司",
  "creditCode": "913502000000000900",
  "registerDate": "2020-03-23 00:00:00",
  "registerAddress": "厦门市思明区软件园",
  "registerCapital": "5000",
  "industryField": "软件和信息技术服务业",
  "highTechField": "新一代信息技术",
  "enterpriseScale": "小型",
  "brief": "人工智能软件研发企业",
  "operationInfoList": [
    {
      "year": "2024",
      "operatingIncome": 99000000,
      "rdExpense": 1000000
    },
    {
      "year": "2025",
      "operatingIncome": 40000000,
      "mainBusinessIncome": 32000000,
      "rdExpense": 3000000,
      "rdExpenseRatio": "0.075",
      "rdPersonnelRatio": "0.1481",
      "employeeCount": 54,
      "rdPersonnelCount": 8
    }
  ],
  "mainTechnologyList": [],
  "mainProductList": [],
  "honorQualificationList": []
}
```

接口也兼容以下包装形式，但推荐直接传企业对象。除 `enterpriseName` 外的企业字段均为可选；字段缺失时遵循既有的“待确认/默认假定”评分口径：

```json
{
  "enterprise": {
    "enterpriseName": "厦门示例科技有限公司",
    "creditCode": "913502000000000900"
  }
}
```

### 3.2 查询参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `policyId` | 否 | 空 | 指定主政策 `fusionPolicyId`；可重复传入多个 |
| `fusionPolicyId` | 否 | 空 | `policyId` 的兼容名称 |
| `policyKeyword` | 否 | 空 | 按政策标题关键词过滤 |
| `policyLimit` | 否 | `0` | 最大匹配政策数；`0` 表示不额外限制 |
| `reviewStatus` | 否 | `1` | 主政策审核状态 |
| `structureReviewStatus` | 否 | `all` | 结构化审核状态 |

指定一条政策：

```http
POST /api/pematching/match/enterprise?policyId=6617
```

指定多条政策：

```http
POST /api/pematching/match/enterprise?policyId=6617&policyId=6652
```

HTTP 状态码：`200`

```json
{
  "success": true,
  "data": {
    "policies": [
      {
        "fusionPolicyId": "6617",
        "applicationStartTime": "2026-08-01 00:00:00",
        "applicationEndTime": "2026-08-31 23:59:59",
        "mainFileTitle": "厦门市企业创新中心授牌申报",
        "issuingDepartment": "厦门市科学技术局",
        "matchScore": 70.0,
        "isRecommended": true,
        "maxAmount": "100万元",
        "documents": [
          {
            "id": "14399",
            "policyTitle": "科技创新类",
            "fileName": "关于举办…的通知.md",
            "filePath": "importantplus/关于举办…的通知/关于举办…的通知.md",
            "policyAttribute": "申报通知",
            "sourcePolicyId": "62"
          }
        ],
        "applicableScope": "厦门市企业",
        "industryField": "软件和信息技术服务业",
        "industryFieldPath": "信息技术/软件",
        "supportMethods": ["资金奖励"],
        "matchStatus": "matched",
        "retryable": false
      }
    ]
  },
  "meta": {
    "runId": "8db4f59cbce84220ad2d4a6ce8c6446e",
    "policyCount": 1
  }
}
```

`data.policies` 按最终分从高到低排序。字段与企业画像需求的对应关系如下：

| 画像页面字段 | 响应字段 | 来源 |
|---|---|---|
| 申报状态、申报时间 | `applicationStartTime`、`applicationEndTime` | `conditions` |
| 政策标题 | `mainFileTitle` | `mainFileTitle` |
| 发文部门 | `issuingDepartment` | `issuingDepartment` |
| 匹配度 | `matchScore` | 本地规则评分结果 |
| 最高奖励金额 | `maxAmount` | `maxAmount` |
| 政策类型 | `documents` | 结构化详情 `documents` |
| 适用范围 | `applicableScope` | `applicableScope` |
| 行业领域 | `industryField`、`industryFieldPath` | `policyInfo` |
| 支持方式 | `supportMethods` | `supportMethods` 的内容文本 |

`matchScore` 为 `null` 表示本次政策匹配未能完成，不能按 0 分理解。模型超时的政策仍保留在结果中，并标记：

```json
{
  "matchScore": null,
  "isRecommended": null,
  "matchStatus": "匹配失败待重试",
  "retryable": true
}
```

### 4.1 完整跑数明细归档

为兼顾外部接口稳定性与后续排查，每次成功运行都会保存一份完整 JSON（包括标准化企业快照、逐政策逐条件得分、风险提示及模型异常信息）。归档目录默认是：

```text
backend/PEMatching/output/enterprise_match_details/
```

可通过环境变量 `PEMATCHING_ENTERPRISE_MATCH_DETAIL_DIR` 覆盖目录。响应只提供 `meta.runId`，不返回服务器绝对路径或完整明细；排查时在归档目录中按 `runId` 查找对应文件。归档写入失败时接口返回 `500`，不会返回没有可追溯明细的成功结果。

## 5. 失败响应

### 企业请求体格式错误

HTTP 状态码：`400`

```json
{
  "success": false,
  "message": "企业信息格式错误：必须提供 enterpriseName。"
}
```

### 未找到已生成规则表的政策

HTTP 状态码：`400`

```json
{
  "success": false,
  "message": "未找到已生成规则表的主政策。"
}
```

### 服务内部错误

HTTP 状态码：`500`

```json
{
  "success": false,
  "message": "具体错误信息"
}
```

## 6. PowerShell 调用示例

```powershell
$page = Invoke-RestMethod -Method Get -Uri "http://112.48.19.225:8500/cms/tb-base-business-info/web/page?pageNum=1&pageSize=100"
$enterprise = $page.data.list[0]

$result = Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8010/api/pematching/match/enterprise" `
  -ContentType "application/json; charset=utf-8" `
  -Body ($enterprise | ConvertTo-Json -Depth 20)

$result.data.policies
```

## 7. 评分口径

- 企业接口提供真实值时，按真实值和规则表计算。
- 企业接口缺少字段时不虚构企业值，按召回优先口径默认具备并记70分。
- 政策要求指定年度但企业只有其他年度数据时，不使用其他年度冒充政策年度；该项企业值保持为空并记70分。
- 明确反证、真实上限超标仍阻止推荐。
- 模型调用超时或连接失败时标记”匹配失败待重试”，不混入普通不推荐结果。

## 8. 前端开发指南

> 后端接口尚未部署时，前端可依据本文档的请求/响应结构先行开发和联调。

### 8.1 推荐开发流程

1. **先定义 TypeScript 类型**——根据本文档第 3、4 节的 JSON 结构，从头文件定义请求体和响应体类型。
2. **使用 Mock 数据并行开发**——按文档示例构造假数据，通过 `MSW`、`setupMock` 或本地 JSON 文件拦截请求，无需等待后端部署。
3. **接口地址配置化**——将服务地址 `http://<PEMatching服务地址>:8010` 提取为环境变量（如 `.env` 中的 `VITE_PEMATCHING_BASE_URL`），后端部署后只改配置即可切换。

### 8.2 前端字段映射速查

| 画像页面区域 | 使用字段 | 说明 |
|---|---|---|
| 政策标题 | `data.policies[].mainFileTitle` | 列表主标题 |
| 申报状态/时间 | `data.policies[].applicationStartTime`、`applicationEndTime` | 用于展示”申报中/未开始/已截止”状态 |
| 匹配度 | `data.policies[].matchScore` | 数值展示在进度条或百分比区域 |
| 发文部门 | `data.policies[].issuingDepartment` | 辅助信息 |
| 最高奖励金额 | `data.policies[].maxAmount` | 字符串型，直接展示 |
| 支持方式 | `data.policies[].supportMethods` | 字符串数组，以标签/徽章展示 |
| 政策类型/行业 | `data.policies[].documents`、`industryField`、`industryFieldPath` | 分类筛选或详情展示 |
| 适用范围 | `data.policies[].applicableScope` | 辅助信息 |

### 8.3 状态处理

**匹配度特殊值：**
- `matchScore: null` —— 不代表 0 分，而是本次匹配未能完成；不要显示”0%”，应显示占位文案如”匹配失败”或”待重试”
- `isRecommended: null` —— 推荐判定同样未完成

**超时 / 失败策略：**
- 当 `matchStatus` 为 “匹配失败待重试” 且 `retryable: true` 时，建议在 UI 中展示重试按钮
- 可对 `retryable: true` 的政策实现自动重试逻辑（建议最多 1–2 次，避免阻塞列表渲染）

**结果为空：**
- `data.policies` 为空数组时，页面展示”暂未匹配到符合条件的政策”空状态

### 8.4 请求参数用法

| 场景 | 参数 | 示例 |
|---|---|---|
| 默认全量匹配 | 不传筛选参数 | `POST /api/pematching/match/enterprise` |
| 按政策ID精确匹配 | `policyId` 可重复 | `?policyId=6617&policyId=6652` |
| 按标题关键词搜索 | `policyKeyword` | `?policyKeyword=创新` |
| 控制返回数量 | `policyLimit` | `?policyLimit=10` |

### 8.5 建议的 API 封装结构（伪代码）

```
api/
  pematching/
    types.ts          ← 请求/响应 TypeScript 类型定义
    mock.ts           ← 基于文档示例的 Mock 数据
    index.ts          ← fetch/axios 封装，读取环境变量中的 baseURL
    useEnterpriseMatch.ts  ← React Hook / Vue Composable（含 loading / error / retry 状态）
```

### 8.6 接口验证清单（上线前对照）

- [ ] 请求体直接传企业对象（不包 `{enterprise: {...}}`）是否能正常返回
- [ ] `policyId` 传多个值时后端是否正确识别
- [ ] `matchScore: null` 的场景是否在前端正确展示（不显示为 0）
- [ ] 400 错误（格式错误/无政策）能否在前端给出友好提示
- [ ] 500 错误的兜底文案
- [ ] 接口超时场景下前端不会白屏或无限 loading
