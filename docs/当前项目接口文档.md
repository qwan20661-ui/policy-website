# 当前项目接口文档

## 1. 文档说明

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 政策解读智能管理系统前端联调仓 |
| 文档范围 | 基于当前仓库 `server.js` 与 `JDBCService.java` 的真实接口实现整理 |
| 对外基准地址 | `http://localhost:3000` |
| JDBC 内部服务 | `http://localhost:8080` |
| LLM 融合服务 | `http://localhost:8003`，可通过环境变量 `FUSION_LLM_URL` 覆盖 |
| 文档口径 | 以 Node 网关对外暴露的 `/api/*` 为主，同时补充当前 Java 已实现但未被网关代理的内部接口 |

## 2. 当前架构

| 层级 | 入口 | 说明 |
| --- | --- | --- |
| 浏览器/前端页面 | `index.html`、`pages/*.html` | 页面统一通过相对路径调用 `/api/*` |
| Node 网关 | `server.js`，默认 `3000` | 负责静态资源、登录会话、API 转发、本地文件读取、LLM 服务代理 |
| JDBC 服务 | `JDBCService.java`，默认 `8080` | 负责达梦数据库查询与写入 |
| LLM 服务 | FastAPI，默认 `8003` | 负责融合类大模型接口 |

## 3. 通用约定

### 3.1 登录与会话

| 项目 | 说明 |
| --- | --- |
| 登录接口 | `POST /api/auth/login` |
| 会话 Cookie | `policy_session` |
| 页面保护 | 未登录访问 `/index.html` 或 `/pages/*` 会被重定向到 `/login.html` |
| API 保护现状 | 当前 `server.js` 对多数 `/api/*` 路由没有统一会话拦截，前端页面主要依赖页面级重定向保护 |

### 3.2 通用响应结构

大部分 JSON 接口采用如下结构：

```json
{
  "success": true,
  "message": "",
  "data": {},
  "pagination": {
    "page": 1,
    "size": 10,
    "total": 100,
    "pages": 10
  }
}
```

说明如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | boolean | 是否成功 |
| `message` | string | 错误信息或提示信息，成功时可能为空 |
| `data` | object/array | 业务数据主体 |
| `pagination` | object | 分页接口返回 |
| `statistics` | object | 部分列表接口会附带统计数据 |
| `options` | array | 基础数据接口会附带筛选选项 |

### 3.3 常见 HTTP 状态码

| 状态码 | 含义 |
| --- | --- |
| `200` | 请求成功 |
| `400` | 参数缺失或参数不合法 |
| `401` | 登录失败或未登录 |
| `403` | 账号禁用等权限问题 |
| `404` | 记录不存在或本地文件不存在 |
| `405` | 请求方法不支持 |
| `500` | 服务内部错误 |
| `503` | Node 无法连接 JDBC 或 LLM 服务 |

### 3.4 二进制/非 JSON 接口

| 路径 | 返回类型 | 说明 |
| --- | --- | --- |
| `/api/attachment/file` | `application/pdf` 或 `application/octet-stream` | 附件预览或下载 |

## 6.4 融合主政策与结构化接口

### 6.4.1 获取融合主政策列表

| 项目 | 内容 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/fusion-classification/policies` |
| Query | `page`、`size`、`keyword`、`reviewStatus`、`markReviewStatus`、`fusionFilter`、`requireSourcePolicyId`、`structureReviewStatus`、`applicationStatus`、`sceneUsage`、`applicableScope` |
| 说明 | JDBC 默认收窄到 `X1_FUSION_POLICY.DEL_FLAG='0'`、`MARK_REVIEW_STATUS='1'`、`SOURCE_POLICY_ID` 非空；传 `reviewStatus=all` 时只取消审核状态过滤，传 `requireSourcePolicyId=0` 时可取消主政策限制。`pages/structure.html` 现在仍显式传 `reviewStatus=1`、`requireSourcePolicyId=1`，并支持 `structureReviewStatus` 结构化审核过滤。高级筛选中 `applicationStatus` 支持 `0=未开始`、`1=申报中`、`2=已结束`；其中 `applicationStatus=1` 除了正常命中 `applicationStartTime <= now <= applicationEndTime`，还会额外返回 `applicationStartTime` 与 `applicationEndTime` 都为空的政策。 |

## 8. 联调注意事项

| 项目 | 说明 |
| --- | --- |
| 页面登录保护 | 页面依赖会话，接口本身没有统一拦截，不要把“页面能打开”与“API 必须登录”混为一谈 |
| `/api/policy/content` | 当前是 Node 二次封装接口，不等同于 JDBC 原生 `/api/policy-original/content` |
| `/api/attachment/file` | 返回二进制流，不是 JSON |
| 结构化页列表 | `pages/structure.html` 当前固定只看“已结构化结果”，并在页面内支持独立的结构化审核通过/撤销 |
| 融合主政策审核 | 审核前要求至少有一条关联文档，且所有关联文档类型都已完成标注 |
| 结构化详情保存 | 关键词是全量替换，保存前要以最新详情为基准 |
| 基础数据清空 | `/api/baseDataRecords/clear` 当前只支持 3 个类型，不支持全部基础模块 |
| 申报条件字典 | Java 已有实现，但当前 Node 网关没有代理；若要前端接入，需要补 `server.js` 路由 |
